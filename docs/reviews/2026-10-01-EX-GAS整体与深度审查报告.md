## 一、执行摘要

项目已有值得保留的 GAS 内核基础：不可变 Catalog、稳定句柄、统一 CommandPort、显式 Tick DAG、事务发布及 Boundary 事实出口。当前更准确的阶段定位是：**以固定 AutoChess 场景验收的 Runtime v1 框架原型**，尚不能据此声明为可自由扩展、可独立安装的通用 GAS 包。

迭代的主要阻力不是缺少更多架构层，而是以下边界没有分开：

1. 框架支持的语义，与样例的固定数量、ID、数值约束
2. 本机已有缓存下的成功，与干净拉取后可重复构建和验证
3. 核心事务安全，与编辑器原始 Excel 写回的数据安全
4. 已交付的受限功能，与历史状态文档中尚未更新的缺失项

优先保留现有安全门，补可复现基线和源数据安全，再证明一个新技能能穿过配置、公开命令与 Boundary 完整链路。不要直接删除 fail-closed 检查，也不要未经需求裁决启动新一轮全面架构重写。

## 二、审查范围与已有资产

静态文件清单包括 3,129 个条目（含目录）；Runtime/V1 有 58 个 C# 文件。全仓数量包含工具、测试、历史资料，不能用数量评价代码质量。本轮重点查看 Runtime 生命周期与支持范围、CodeGen/Authoring、AutoChess 集成、测试脚本、包依赖、ADR 和当前进度文档，并未逐行检查全部文件或二进制资产。

- immutable Catalog 与独立身份校验
- 外部提交 intent/command，内核按固定顺序推进

- Boundary 投影作为表现和诊断出口

### R1 / P1：能力准入混入样例黄金数据，阻挡普通配置迭代

**类型：明确的阶段性设计限制，不是误写一行代码。**

Editor 的 RuntimeV1RawAuthoringSupportProfileAdapter 精确要求玩家/敌人基础伤害 12/8、特定 finisher 公式和 poison 系数。AutoChessDemoConfigModel 在生成前调用该检查，统一 Pipeline 同时处理 Core 与 AutoChess。因此在当前导表生成路径中，把 12 改成 13 也会被拒绝。

Runtime 另有支持面检查：限定 3 属性、0 tags/requirements、4 abilities/effects、指定 ID，关闭 cost/cooldown。不要混淆两层：Runtime fixed-instant 校验并非同样把伤害锁为 12/8；精确数值锁定发生于 raw authoring 层，Runtime 还独立限制形状和能力。

### R3 / P1：Dispose 后同一 caller-owned World 的重新安装不闭合

Dispose 关闭 ingress、退出自动 PlayerLoop、FinalDrain 并删除 registration，但保留 GAS systems。同一 World 再 Install 会创建新 gate，GetOrCreate 复用旧 ingress system；Bind 明确拒绝绑定另一 gate，形成可由源码推导的异常路径。

证据：[Dispose](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Runtime/V1/Session/GasRuntimeWorldOwner.cs#L458-L492)；[Install](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Runtime/V1/Session/GasRuntimeWorldOwner.cs#L268-L294)；[拓扑绑定](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Runtime/V1/Session/GasRuntimeWorldOwner.cs#L588-L595)；[禁止重绑](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Runtime/V1/System/GasCommandIngressSystem.cs#L69-L78)。

另需验证：宿主直接继续更新原 World 时，Kernel 查询依赖 Session authority，BatchFence 依赖已删除的 registration；存在继续推进而不完成原收尾路径的风险。FinalDrain 不等同于撤销所有 live Session/ASC authority。

**建议：**明确 owner 的停机与卸载合同，先停止执行域，再排空，最后安全解绑或卸载。不要只放开 Bind 而留下旧 session/journal。

**验收：**Install→Dispose→Install；Dispose 后继续 update；重复 Dispose；drain 失败后的重试。分别检查 tick、Health、period、fact、旧请求和新 gate 归属。当前 Demo 关闭时销毁 World，不能据此声称它已触发该问题。

### R4 / P1：Excel 写回使用过期物理行号，可能修改或删除错误记录

GASCenterExcelTable.Load 缓存 ID→行号。Save/Delete 重新打开磁盘工作簿，却使用原行号，不检查文件变化或当前行 ID。UI 同时提供外部打开 Excel 与保存。

**触发：**加载 A 在第 N 行→外部插行/排序→不刷新→保存或删除 A。写入可能覆盖 B，删除也可能作用于 B。事后导表校验不能恢复源数据。

证据：[缓存与写回](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Editor/GASCenterUIToolkit/GASCenterExcelTable.cs#L47-L148)；[外部编辑入口](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Editor/GASCenterUIToolkit/GASCenterAbilityPage.cs#L64-L73)；[保存调用](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/b87745639bce1ccff60f794153c7cb54b0bdee50/Assets/GAS/Editor/GASCenterUIToolkit/GASCenterAbilityPage.cs#L339-L353)。

同一读取循环遇到空 ID 即停止，重复 ID 静默覆盖字典；可能使后续行在编辑器中不可见。应统一处理，而非各页面修补。

**建议：**写前比较加载快照与当前文件，冲突时拒绝并提示重载/合并；按当前工作簿重新定位唯一 ID；重复/非法 ID 阻止写入；临时输出校验后替换。

**验收：**外部插行、排序、删行、空 ID、重复 ID 后保存/删除，目标和非目标记录均符合预期，失败不破坏原文件。

## 六、建议推进顺序与验收

以下是建议，不是已批准或已实施的架构变更。

1. **可重复基线**：补必要 .csproj 和 bootstrap；修 runner 退出码/超时判定；从干净副本完成与固定 SHA 绑定的最小验证并发布证据
2. **源数据与生命周期安全**：修 Excel 冲突/ID校验；明确 Dispose/再安装合同；补最小回归
3. **一条新技能完整链路**：新增不同 ID 的单体即时伤害，仅用现有语义；不同时加入 cost、cooldown、AOE、网络预测
4. **按真实目标决定复用边界**：若优先通用框架，让第二消费程序集不引用 AutoChess 完成同一技能；若优先实际游戏，将其接入真实游戏循环
5. **规模与发布**：功能支持面稳定后再做目标规模、IL2CPP、Profiler、长期运行与数值确定性验收

第三步的完成定义：
- authoring → generation → Catalog → 公开 Activate/Commit → Boundary 精确结果
- 新增技能不修改 Runtime 固定 ID、固定数量或技能专属分支
- 重复请求不重复扣血；非法配置明确拒绝；原样例回归保持
- 结果绑定配置、源码与测试证据身份，不能只把 Pending 改成 Green
