## 偏离、影响与判定边界

### M03-P2-01：IBC 全零仍缺本审计可验证的选型证据

触发：把当前布局用于新的大规模/不同Catalog产品负载。IBC=0 本身是合法官方 API，不是错误；BUF-01/04要求以代表性长度分布、外部化、chunk capacity和实际成本验证选型。本次只确认代码选择，未读到对应逐类buffer的profile闭包，因此列“未验证/发布证据门”，不声称性能退化或内存超标。profile证明后可直接关闭，不要求机械改为非零。

### M03-P2-02：目标资源预算维度未在现有 profile 类型中表达

触发：启用 Spec13-03 §7 中完整 hot-target工作预算、target shadow/durable双份预留验收。当前profile主要是记录数上限，未显式包含该节要求的work units与双份credit。影响：不能仅凭字段非负和EnsureCapacity就宣称 JOB-06完整上界证明已消费。应由Kernel/Proof模块确认等价表达是否存在；未发现等价实现前保持“目标差距”，不改判成当前已支持路径的已复现溢出。

### 生命周期名称冲突

Spec13-01旧概念表仍列简化Session enum；90不变量/BND-14更具体地要求最终receipt/seal流程。本审计遵循较具体目标，不能以简化表把完整关闭协议抹去，也不要求协议状态必须与同名enum一一对应。

## API / ECS 适用性说明

| 维度 | 本模块答案 |
|---|---|
| Tick | 只定义持久布局；fixed buffer初始化属于spawn，热路径不resize需查writer |
| owner | Session owns registry/config；ASC owns long-lived slabs；Boundary owner通过cleanup state冻结 |
| 数据/API | IComponentData/IBufferElementData/ICleanup*，固定archetype；DynamicBuffer按owner访问；不需要新增System |
| allocator | DynamicBuffer由ECS生命周期管理；Blob registry是引用，不在此Dispose；无跨Tick临时NativeContainer字段 |
| 结构变化 | CreateArchetype只建布局；Entity创建/销毁由调用者标准EndFixed负责；不能把EnsureCapacity误写为archetype变化 |
| drain | 类型支持destroy后保留，是否唯一消费者、receipt成功后清理见Boundary模块 |
| ScaleProfile | 有版本/hash及逻辑容量，IBC选型实测、chunk利用率和shadow/work维度仍待闭包 |
