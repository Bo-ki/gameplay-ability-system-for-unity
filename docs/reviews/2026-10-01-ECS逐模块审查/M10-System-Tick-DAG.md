## 3. 实质检查与改进

### M10-01：串行 target wave 与目标并行化之间存在明确差距（P1，目标能力）

触发规模：多个独立 target 同 Tick 有 effect/period 工作。当前单 IJob + registry loop 保持顺序和同 target 单 writer，但所有 target 共用串行执行路径及 evaluator scratch。影响是未实现规范指定的 target-bucket parallelism；**不声称已测出某毫秒退化**。

建议：先生成稳定 target ranges，每 target 给独占 shadow/evaluator/output partition；并行 prepare 后 canonical reduce，再 no-fail publish。不得直接添加 NativeDisableParallelForRestriction 来“解决”重叠检查。

验收：1/多个 worker、均匀目标/热点目标都得到相同语义 hash；证明写集合互斥；提供 JOB-01 API选型理由及 scheduling、execution、sync 分离曲线。依据见矩阵 JOB-01、API§5、PRF-19。

### M10-02：按配置峰值分配 shadow + ECB 临时副本，缺乏采样证据（P1性能验证门，非已测故障）

Scratch 为 registry上限×effect/payload上限分配平面；Period阶段所有 Ready owner 都准备7个buffer；应用阶段从shadow再次拷贝；publish再复制到durable。[GasTickJobs.cs:4956–5055](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/61daa507e52e823ff42a8cb8c8ec91716c7e80e7/Assets/GAS/Runtime/V1/System/GasTickJobs.cs#L4956-L5055)、[GasTickJobs.cs:6850–6935](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/61daa507e52e823ff42a8cb8c8ec91716c7e80e7/Assets/GAS/Runtime/V1/System/GasTickJobs.cs#L6850-L6935)。

优点：以副本隔离 target fatal，范围检查采用 long/减法避免乘加越界。代价：当前活动数远小于上限时，allocation/zero/copy仍可能由上限主导。ECB系统拥有临时buffer且禁playback，未发现手工dispose该ECB造成双释放。

建议：量化每Tick与outer batch分配字节/清零/复制量、hot-target偏斜；评估按真实owner/work count的prefix partitions或稀疏overlay，并保持admission可证明上界。验收覆盖0/1/N Tick，记录double-rewind真实高水位；仅功能跑绿不通过此项。

### M10-03：Dispose后执行域与gate寿命不一致（P1，确定源码缺陷）

本项是跨模块影响说明，主发现归属 [M01-Session-World.md](M01-Session-World.md) 的 **M01-P1-02**；修复/Issue只登记一次，不另拆重复问题。

触发：Install(world)→Dispose()→Install同一个仍存活world。Dispose删除registration却保留system，Install查不到registration创建新gate，GetOrCreate拿到旧ingress，Bind抛异常。[GasRuntimeWorldOwner.cs:268–294](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/61daa507e52e823ff42a8cb8c8ec91716c7e80e7/Assets/GAS/Runtime/V1/Session/GasRuntimeWorldOwner.cs#L268-L294)、[GasRuntimeWorldOwner.cs:588–595](https://github.com/Bo-ki/gameplay-ability-system-for-unity/blob/61daa507e52e823ff42a8cb8c8ec91716c7e80e7/Assets/GAS/Runtime/V1/Session/GasRuntimeWorldOwner.cs#L588-L595)。

若宿主直接继续更新原World，Kernel query仍可命中未撤销Session authority；batch fence因registration不存在停止。当前Demo是否每次new/dispose整个World不在本模块结论内，不能说现有Demo必挂。

建议明确terminal→final drain→停止域→解绑/销毁system的状态转换，或者把不可复用契约显式化并真正阻断旧域。验收：Dispose后更新原World若干fixed steps，Tick/Health/period不变；同World重装成功且唯一gate，或按明确API契约在修改前拒绝。

### M10-04：no-fail发布的维护风险，应补证明而不是编造现行bug（P2）

TargetPublish之后LifecyclePublish仍可能把Decision重置失败；下一reduce会阻止后续terminal/boundary发布。当前preflight已检查相同identity/slab/child/commit条件，尚无有效输入反例。不能仅凭存在false分支认定原子性已破坏。

建议把所有publish条件纳入同一个prepare token，或用生成/共享验证避免两份条件漂移。验收故障注入应分别覆盖target preflight、lifecycle preflight、boundary prepare，验证target durable/fact/ECB零半写和owner committed-prefix保留。

## 4. 优点与未完成门

优点：单Kernel集中ownership；显式JobHandle链；标准EndFixed；target shadow防止可预见失败直接污染durable；请求和事实有稳定身份；当前one-shot normal End已接通，不能复述旧“无End”结论。

未完成门：所有Stage B路径逐分支审查、Burst/AOT、safety checks、race/leak、0/1/N fixed tick、parallel determinism、每目标budget、p95/p99与Native高水位。**本报告不给性能通过或完整目标态完成结论。**
