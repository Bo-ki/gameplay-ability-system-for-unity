# SC-02: 区分直接数据引用失效与缓存 Handle 更新

**严重度**: P0
**Primary Owner**: 结构变化-ECB
**类型**: EX-GAS 项目规则
**证据等级**: 项目推导（官方机制以“来源”列出的精确版本文档为准）
**适用版本**: Unity 6000.3.14f1；Entities 1.4.6
**来源**: `concepts-safety.md`、`performance-sync-points.md`、`components-buffer-introducing.md`、`systems-systemapi.md`、`systems-optimizing.md`

## 规则声明

结构变化可能移动 chunk 数据，因此此前取得的直接数据引用（例如 `DynamicBuffer<T>`、`RefRO/RefRW`、chunk `NativeArray` / `BufferAccessor`）必须重新获取。缓存为 system 字段的 `ComponentTypeHandle`、`BufferTypeHandle`、`ComponentLookup`、`BufferLookup` 可以复用其 struct，但必须在下一次使用或调度前调用 `.Update(ref state)` 刷新；不要求每次销毁并重新创建字段。`EntityQuery` 本身可缓存并会跟踪后续出现的匹配 archetype。

## 为什么

结构变化会使指向旧 chunk 内存的直接引用成为悬垂引用，安全检查通常会抛异常。TypeHandle/Lookup 是携带类型、安全与缓存状态的访问器，生命周期规则是“缓存后按使用点 Update”，不能与 `DynamicBuffer` 等直接引用混为一谈。

## EX-GAS 诊断

曾出现 `DynamicBuffer invalidated by structural change` 安全异常，源于 EffectApplication 系统中在 buffer 操作前后存在隐式结构变化。

## 检查方法

Code review 时检查结构变化后是否继续使用此前获取的直接引用，并检查缓存 TypeHandle/Lookup 在下一次使用前是否 Update。优先把结构变化推迟到 playback phase，减少同一执行段内重新获取的需求。
