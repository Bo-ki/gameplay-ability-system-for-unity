# SC-01: Hot Path 禁止直接结构变化

**严重度**: P0
**Primary Owner**: 结构变化-ECB
**类型**: EX-GAS 项目规则
**证据等级**: 项目推导（官方机制以“来源”列出的精确版本文档为准）
**适用版本**: Unity 6000.3.14f1；Entities 1.4.6
**来源**: `performance-sync-points.md`、`systems-entity-command-buffer-use.md`、`optimize-structural-changes.md`

## 规则声明

EX-GAS Runtime Core hot path 默认禁止散落调用 `EntityManager.CreateEntity`、`DestroyEntity`、`AddComponent`、`RemoveComponent`，并把 job 产生的命令录制到约定 ECB。需要立即可见或适合 `EntityQuery` bulk API 的主线程变更可作为有证据例外，不使用统一实体数量阈值。

## 为什么

直接结构变化会完成所需 job，并使组件数据的直接引用失效。连续变更之间若没有新调度 job，不一定每次都有新的实际等待；真正需要避免的是反复交错“调度 job → 结构变化”。

## EX-GAS 诊断

[ISSUE-004](<../../../针对2.0的ECS架构的迭代方案讨论/00-当前架构事实/ISSUE-004-结构变化边界脆弱.md>) 的旧 request-entity 链路已经退场，`GASStructuralCommitSystemGroup` 也已成为真实 gate；当前风险是边界与初始化路径仍存在直接 EntityManager 操作，尚需完成分类和 Journaling 来源证据。旧类名只属于历史故障背景，不代表当前实现。

## 检查方法

搜索代码中 `EntityManager.CreateEntity` / `DestroyEntity` / `AddComponent` / `RemoveComponent` 在 `OnUpdate` 或 job 中的出现；Debugger 向违规 system 告警。
