# 21 官方文档覆盖与流程闭环

## 定位

本文件定义官方依据如何进入主题文档、EX-GAS 规则、行动报告、任务树、目标态和当前事实。它是项目治理流程，不是 Unity 官方规范。

**类型：** EX-GAS 项目治理规则

**适用版本：** 与 [版本与 PackageCache 证据](../元信息/版本与PackageCache.md) 同步

## 闭环

```text
精确 PackageCache 文档/源码
  → 标注官方事实或官方建议
  → 分离 EX-GAS 项目推导与项目基准
  → 选择 Primary Owner 和规则编号
  → 更新主题入口、全局索引和受影响项目文档
  → 执行链接、编号、快照和版本验证
```

## ODF 规则

| 编号 | EX-GAS 治理规则 |
|---|---|
| `ODF-01` | DOTS 任务先读 README，再从相关主题 `_index.md` 进入，不以旧数字聚合文档为正文。 |
| `ODF-02` | 行动报告记录 Unity Editor、精确包版本和 PackageCache hash，不写“latest”。 |
| `ODF-03` | 官方依据改变目标态设计时，反哺 `01-目标态架构共识`。 |
| `ODF-04` | 官方依据暴露当前实现问题时，反哺 `00-当前架构事实` 并附规则编号。 |
| `ODF-05` | 官方依据改变任务顺序或验收时，反哺 `02-主线任务树`。 |
| `ODF-06` | 官方依据改变工作流时，更新 Primary Owner 主题和治理文档。 |
| `ODF-07` | 本轮临时发现先进入迭代摘要，再决定是否升级为长期事实。 |
| `ODF-08` | 旧数字聚合文档只保留兼容跳转，不维护第二份正文。 |
| `ODF-09` | 性能证据分离 core、physics、render、runner，禁止混合归因。 |
| `ODF-10` | 交还证据包含可复现环境：版本、AOT/JIT、World、allocator、测试场景。 |
| `ODF-11` | `官方文档原件` 与精确 PackageCache 逐文件比较路径和 SHA-256。 |
| `ODF-12` | Burst 结论区分 Editor JIT 与 Player AOT，并记录 Safety Checks、架构和编译选项。 |
| `ODF-13` | Managed boundary 明确 Core 与 Presentation/Debugger 的所有权和数据流方向。 |
| `ODF-14` | Baking、Content 与 allocator 结论分别记录依赖、加载/释放和内存所有权。 |
| `ODF-15` | 涉及 Physics 时读取 UnityPhysics 主题；不相关时写明边界理由。 |
| `ODF-16` | Physics 证据记录 timestep/rate manager、broadphase 时效、事件窗口和物理配置。 |
| `ODF-17` | 涉及 Entities Graphics 时读取对应主题；结构变化遵循 Presentation 子组约束。 |
| `ODF-18` | Render 证据独立记录 render profile，不以有头帧耗时替代 Core 成本。 |

## 发现的归属

| 发现类型 | Primary Owner |
|---|---|
| API 机制、生命周期、限制 | 对应主题的 `API与EX-GAS解读.md` |
| 项目规则或模式 | 对应主题的原子规则文件 |
| 跨主题编号和 Owner | `元信息/90-规则编号索引.md` |
| 版本、hash、快照状态 | `元信息/版本与PackageCache.md` |
| 目标设计、当前问题、任务顺序 | 仓库相应架构/事实/任务文档 |

```markdown
- 读取主题：Query-Job-遍历、结构变化-ECB、...
- 采用：<API/模式 + 官方机制依据 + 项目理由>
- 拒绝：<候选 + 具体理由>
- 暂不相关：<主题 + 边界理由>
- 证据等级：<官方事实/官方建议/项目推导/项目基准>
- 需要反哺：<owner 或“无”>
```

## 验收

1. 所有 ODF-01～18 均有规则正文，可按相关/不相关逐项判断。
2. README、主题入口、全局索引和原子规则形成单一事实源。
3. 规则编号唯一，旧聚合文档不保留正文。
4. 官方原件快照、版本表和来源文件名通过自动扫描。
