## 阅读顺序

1. 先读 `16-01A`，确认为什么要把 OOP Shell、Runtime Boundary、Pure ECS Core、Definition & Generation 拆开。
2. 再读 `16-01B`，用 Owner Map 和验收表判断新设计是否仍把复杂度藏回 Shell、generated lifecycle 或 Debugger。
3. 然后读 `16-01C`，确认业务 intent、command record、snapshot、evidence 和 pure glue 的消息方向。
4. 最后读 `16-01D`，用最小完整判定门检查 Interface 是否比 Implementation 更窄；需要完整代码正文时跳到 `16-06`。
