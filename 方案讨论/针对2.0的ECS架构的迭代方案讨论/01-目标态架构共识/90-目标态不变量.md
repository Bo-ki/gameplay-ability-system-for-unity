# 目标态不变量

1. GAS Runtime Core 权威只在 ECS 数据中。
2. 外部写入只通过 request entity 或等价 command data。
3. 外部观察只通过 mirror、outbox、replay、debugger、read model。
4. Definition & Generation Layer 不携带 runtime state。
5. Runtime state 不反查 managed authoring config。
6. Cue / Presentation 不决定 gameplay。
7. System 调度显式、可测试、可追溯。
8. Editor authoring 不引入 runtime source dependency。
9. Generated pipeline 只强化已经稳定的 contract，不发明新语义。
10. UE GAS、tranek、方案1-15 都是参考来源，不替代当前代码事实和 Unity ECS 第一性约束。
11. 性能优化不能提前吞掉 GAS 语义问题。
12. Debug / Replay 是事实记录，不是状态权威。
13. 性能结论必须标明采样口径；默认只接受 `ecsRuntimeTickOnly` 作为 ECS Runtime tick 讨论基础。
14. 高频业务 reaction 应使用 typed facts / cursor / stable ECS state。
15. Simple instant GE 可以绕过 request entity / 临时 GE instance 热路径，但不能绕过 GAS 事实语义。
16. ECB playback 是结构变化成本，也是同批 GE apply 的语义可见性屏障。
17. Runtime Core Debugger 是运行健康事实流，不能反向驱动 GAS Runtime Core。
18. 类型名、任务名和目录名必须表达四层归属、读写方向和状态职责。
19. Unity Entities 1.4.6 的 SystemGroup / ISystem / Job / ECB / Enableable / DynamicBuffer / Blob / Baker / Query filter 是 Runtime Core 目标态的第一性技术约束。
20. request entity 不是高频 instant GE 的默认承载；高频路径优先 command data / buffer / stream。
21. hot path 中直接执行结构变化是 P0 违规；结构变化只能在明确的 `GASStructuralCommitSystemGroup` playback 中发生。
22. DynamicBuffer 不是无限全局消息总线；每类 buffer 必须有容量、生命周期、清空策略和 pressure counters。
23. EntityQuery change filter 是 chunk 级优化，不是精确 gameplay event 语义。
24. Runtime Core 新增 system 必须先回答所属物理执行域 SystemGroup、所属 kernel lane、读写集合、结构变化权限、buffer 生命周期、query filter、Debugger counters；新增 SystemGroup 必须额外证明存在新的同步/结构变化/投影物理边界（`SYS-03` `PRF-07`）。
25. 业务代码评审必须引用 `UnityDOTS官方文档参考/主题/90-规则编号索引.md` 的具体规则编号，不能只引用抽象原则。
26. Runtime Core API 选型必须引用 `UnityDOTS官方文档参考/主题/20-GASRuntimeCore-API选型基线.md`；未评估 `NativeStream`、Chunk Component、Cleanup Component、EntityQuery bulk、system-associated entity、WeakObjectReference / UnityObjectRef 等候选 API 时，不得把当前实现承载视为目标态。
27. Runtime Core 每帧必须能解释 query/filter/allocator/dependency 的成本来源；这些成本不是 Debugger 后补指标，而是目标态 phase contract 的一部分。
28. DynamicBuffer 溢出、chunk fragmentation、shared component unique value、enableable wait、job scheduling overhead 都属于架构健康问题，不得被归类为普通优化项。
29. ExecutionCalculation 目标态不使用托管 delegate 或可变静态注册表；动态计算必须能被 Burst job、generated static switch 或经证明的粗粒度 FunctionPointer 承载。
30. 无头验收不删除表现链路；Cue / UI / VFX / SFX 仍从 Boundary outbox 派生，只是最终 side effect 可替换为结构化日志。
31. AutoChess deterministic 验收必须明确 world time / tick source；不得用 Editor frame delta 或首帧 Burst 编译数据判断 Runtime Core 性能。
32. 目标 Archetype 数量 < 10；不使用 tag component（纯标记无数据字段）—— gameplay tag/status 默认通过 `TagMaskComponent` / `TagStatusFlagsComponent` / enum bit field 表达，enableable 仅用于明确拥有状态且经 profile 证明的 skip 场景。
33. 每个 DynamicBuffer 必须有 `InternalBufferCapacity` 声明和 spill 监控；buffer 外部化是性能退化信号，不是"能用就行"。
34. 每种 Component 必须明确分类为 Data/Buffer/Enableable/Chunk/Cleanup 之一；禁止"ECS component"笼统称呼掩盖选型决策。
35. Frame Prepare（frame clock / allocator / dependency / query-lookup budget）是 Runtime Core 的前置基础设施，不是可选优化；hot path 禁止临时创建 EntityQuery，Lookup / TypeHandle 必须由 owner `ISystem` 在 `OnUpdate` 刷新并被 Debugger 计数。
36. Enableable toggle 只在明确拥有状态的 lane 执行：高频状态归 `GASCoreSimulationSystemGroup` 的 State lane，grant/revoke/destroy 归 `GASStructuralCommitSystemGroup`；Target Resolve / Effect Fan-In / Attribute Reduce-Apply / Gameplay Fact lane 对 enableable 只有只读访问；同步 enableable-filtered query 不得在 hot path 无评估使用。
37. Chunk Component 是性能优化，不替代 per-entity 状态正确性；使用 Chunk Component 的 phase 必须有 Debugger 一致性验证。
38. 禁止使用已废弃的 DOTS API（如 `IAspect`，deprecated since Entities 1.4.6）。所有 API 选型必须以当前 PackageCache 版本的非 deprecated API 为准；统一替代方案为直接 component 访问和 query 方法。已有 `IAspect` 使用需在重构窗口替换，新代码不得引入。参见 `P1-09`、`CASE-13`。
39. Runtime Core job 内结构变化默认录制 ECB，并在 `GASStructuralCommitSystemGroup` 的明确 playback phase 合并执行；禁止从 Job 内部直接调用 `EntityManager`。`ExclusiveEntityTransaction` 仅限 secondary/streaming World 的窄口批量结构变化，不是 ECB 等价物，也不是通用 worker-thread `EntityManager` 替代（`PRF-21`）。
40. EntityQuery 创建必须通过 `SystemState.GetEntityQuery`，禁止使用 `EntityManager.CreateEntityQuery`（`PRF-33`）。通过 SystemState 创建的 query 能被安全系统追踪、参与 dependency 管理；直接 `EntityManager` query 无法被系统自动管理生命周期和依赖完成。
41. ASC Entity 批量创建必须使用预建 Archetype（`EntityManager.CreateArchetype`），禁止逐 Component 添加（`P1-14`）。逐 Component 添加产生 N-1 个冗余中间 Archetype 永久存在，增加所有 EntityQuery 计算开销。
42. 同一游戏模式内所有 ASC Entity 默认具有相同 AttributeSet family 组件集合；不同角色“不使用某属性”优先通过默认值、tag requirement 或 effect requirement 表达，不通过移除属性 component 表达。
43. NativeContainer（含 `AllocatorManager.AllocatorHandle`）放在 `IComponentData` 上时，禁止对该 entity 调度 `IJobChunk`/`IJobEntity`（`PRF-34`）。主线程提取 handle 后作为 Job 参数传入。
44. `IJobEntity`/`IJobChunk` 中使用 `ComponentLookup`/`BufferLookup` 随机访问其他 entity 时，必须确保被访问 entity 集合与 job 直接遍历的 entity 集合无数据重叠，否则标记 `[NativeDisableParallelForRestriction]` 并附安全证明（`PRF-19`）。优先方案：owner-local buffer 替代跨 entity lookup（`PRF-06` `QRY-04`）。
45. Attribute 默认实现为 generated AttributeSet family，并按真实热路径/变更频率拆成 Current set 与 Base/Config set；不再默认“一属性一 component / 一属性一 system”。Current 高频写与 Base 低频写必须分离，避免高频写触发 Base 的 ChangeFilter 误触发。
46. 独立 per-attribute component 只允许作为有 profiler/query contract 证明的例外，且必须证明新增 component type、system/handle 成本和 archetype 变化仍低于收益。
47. Runtime assembly 不得依赖 `cfg.*`、`XLuban`、`SimpleJSON`、Luban managed row 或 JSON table reader；Runtime Core 只消费 generated ids、`GASDefinitionCatalogBlob` / Blob、unmanaged lookup、Generated Runtime Glue、component type 和 static switch。
48. 静态定义 Blob 必须从 Luban row、generated definition 或 Baker 输入构建；禁止从 prototype entity、runtime component 或 active effect state 反推静态 definition。
49. 生成链必须有单一 metadata context、Phase manifest、输出路径审计和 orphan `.g.cs` 清理机制；重复反射扫描和分散硬编码推断只能作为迁移期债务。
50. Generated static lookup / calculation registry 必须 Burst 可读且具备明确生命周期；托管数组、managed dictionary、托管 delegate 和可变静态 registry 不得进入 Runtime Core hot path。
51. Baker 生成物必须是 stateless `Baker<TAuthoring>` 或显式 Baking System plan；静态 ECB helper 不能作为目标态 authoring / baking 边界。
52. `IJobChunk` 的 query 若包含 enableable component，`Execute` 必须在 `useEnabledMask == true` 时使用 `ChunkEntityEnumerator` 或 `EnabledMask`；`useEnabledMask == false` 时可走普通 `for` 快路径。若确认 query 永不含 enableable mask，必须显式断言 `useEnabledMask == false`（`PRF-22` `CASE-26`）。
53. 每个并行 Job 使用独立 ECB；多个并行 Job 禁止复用同一个 `EntityCommandBuffer` 实例，除非能证明 sortKey 域不重叠且回放顺序不影响确定性（`PRF-25`）。
54. Status / Buff / Debuff 类标记超过 3 个独立状态时，必须合并为 `TagMaskComponent` / `TagStatusFlagsComponent` / enum bit field；禁止每个 status 一个 tag component 或 enableable component（`PRF-03` `FSM-05`）。
55. Runtime Core 中同时包含只读配置字段和高频读写字段的数据结构必须拆分；使用 change filter、reactive projection 或 typed fact 监听时，禁止因 `ref` 访问只读字段导致 chunk 误标 changed（`PRF-26`）。
56. Runtime Core 目标态 SystemGroup 只表达物理执行域，默认固定为 `GASFramePrepareSystemGroup`、`GASCommandResolveSystemGroup`、`GASCoreSimulationSystemGroup`、`GASStructuralCommitSystemGroup`、`GASBoundaryProjectionSystemGroup`；Boundary/Target/FanIn/State/Attribute/Fact 是 lane，不默认建 group。
57. CoreSimulation 默认单帧数据流必须是有向无环图；`Gameplay Fact` 触发的新 GE 默认写 next-frame command seed。若业务必须同帧连锁，必须显式声明 bounded reaction pass、最大 pass count、cutoff reason 和 Debugger counters。
58. Luban / SourceGenerator 进入 Runtime Core 的默认形态是 `GASDefinitionCatalogBlob` + generated code->index lookup + Generated Runtime Glue；`GASGeneratedDefinitionBlobComponent<T>` 的 per-definition entity 只允许作为 baking output / bootstrap 收集入口，不作为 hot path lookup（`BLOB-01` `QRY-04`）。
59. Runtime-visible generated artifact 不得包含 `: ISystem`、`OnUpdate(ref SystemState)`、system registration、`CreateSystem(`、`AddSystemToUpdateList(`、`state.EntityManager`、ECB、`SystemAPI.Query`、`ComponentLookup` / `BufferLookup` owner 或 NativeContainer owner。除非标记 `MigrationProofOnly` 且绑定移除任务，否则视为目标态失败（`SYS-01` `SYS-03` `QRY-01` `QRY-04` `SC-01` `ECB-03` `NAT-03` `BUR-01`）。
60. SourceGenerator 只生成 definition / blob / lookup / Baker glue / query hint / validation report / static pure glue；Runtime Core lifecycle、query ownership、dependency ownership、allocator ownership、ECB ownership 和 NativeContainer ownership 必须由手写 ECS System 拥有。
61. Definition Catalog singleton 在 bootstrap / scene load 后不可写；Runtime system 只能只读获取 `BlobAssetReference<GASDefinitionCatalogBlob>` 并传入 job。singleton API 不完成依赖，因此禁止在 runtime tick 内写 `GASDefinitionCatalogComponent`。
62. `GASGeneratedDefinitionCatalogBuilder.BuildCatalog()` 或等价 `BlobBuilder` 入口只能属于 Baking / Bootstrap / initialization owner，并明确 runtime-created Blob 的 dispose owner；Runtime Core hot path 不调用 builder（`BLOB-02`）。
63. 含 `BlobArray` / `BlobString` / `BlobPtr` 的 definition 数据必须通过 index + `ref readonly` 访问；lookup API 禁止按值返回 Blob 元素。
64. Generated Runtime Glue 必须是静态纯函数 + unmanaged record：`AbilityDefinitionIndex -> AbilityActivationPlanRecord -> GECommandSeedRecord -> ResolvedModifierRecord`。禁止把 glue 实现成 singleton、manager、strategy object、runtime lifecycle system 或 hidden ECB/query。
65. Definition Catalog 的可变长数据默认使用 root `BlobArray` + `Start/Count` range 表达；Ability / GE definition 只保存 index、range、code 和 policy，不保存嵌套 runtime state。
66. 使用 `NativeStream` / `NativeList` 连接 Runtime lane 时，owner system 必须显式串联 JobHandle 并负责 dispose/rewind；ECS `Dependency` 不会自动追踪 NativeContainer 之间的数据流。
67. Application Shell 可以拥有面向业务的 Battle Runtime Adapter seam，但该 seam 不得成为 OOP gameplay 中间层。Adapter 对外 interface 只表达业务 runtime 动作；direct `EntityManager`、catalog lifetime、ASC lifecycle、observation reset、official diff 必须在 implementation 内按 owner 分类并可审计。
68. AutoChess headless runner、scene runner、Profiler pass 和 official diff pass 必须共享同一 validation evidence model；字符串 summary、Mermaid 图和中文日志只是导出格式，不是验收事实源。
69. AutoChess unit / scenario / scale profile / validation expectation 的长期事实源必须来自 Luban / SourceGenerator 生成物；`GameRoomFactory`、runner 常量、serialized fields 或 managed row array 只能作为迁移期 proof。
70. ExecutionCalculation 业务公式必须进入 generated evaluator / static switch / batch path；ECS system 中硬编码 calculation code、GE code 或公式只能作为 proof-only，并必须提供重新选型触发条件。
71. CodeGen validation report 必须检查 generated lifecycle / ownership / random lookup / NativeContainer owner / structural change hits；只检查 forbidden dependency 或 naming debt 不足以证明生成链路达标。
