# 目标态不变量

1. GAS Runtime Core 权威只在 ECS 数据中。
2. 外部写入只通过 request entity 或等价 command data。
3. 外部观察只通过 mirror、outbox、replay、debugger、read model。
4. Definition & Generation Layer 不携带 runtime state。
5. Runtime state 不反查 managed authoring config。
6. Cue / Presentation 不决定 gameplay。
7. System 调度显式、可测试、可追溯。
8. Editor authoring 不引入 runtime source dependency。
9. Generated pipeline 只强化已经稳定的 contract，不发明新语义。
10. UE GAS、tranek、方案1-15 都是参考来源，不替代实现代码事实和 Unity ECS 第一性约束。
11. 性能优化不能提前吞掉 GAS 语义问题。
12. Debug / Replay 是事实记录，不是状态权威。
13. 性能结论必须标明采样口径；默认只接受 `ecsRuntimeTickOnly` 作为 ECS Runtime tick 讨论基础。
14. 高频业务 reaction 应使用 typed facts / cursor / stable ECS state。
15. Simple instant GE 可以绕过 request entity / 临时 GE instance 热路径，但不能绕过 GAS 事实语义。
16. ECB playback 是结构变化成本，也是同批 GE apply 的语义可见性屏障。
17. Runtime Core Debugger 是运行健康事实流，不能反向驱动 GAS Runtime Core。
18. 类型名、任务名和目录名必须表达四层归属、读写方向和状态职责。
19. Unity Entities 1.4.6 的 SystemGroup / ISystem / Job / ECB / Enableable / DynamicBuffer / Blob / Baker / Query filter 是 Runtime Core 目标态的第一性技术约束。
20. request entity 不是高频 instant GE 的默认承载；高频路径优先 command data / buffer / stream。
21. hot path 中直接执行结构变化是 P0 违规；结构变化只能在明确的 `GASStructuralCommitSystemGroup` playback 中发生。
22. DynamicBuffer 不是无限全局消息总线；每类 buffer 必须有容量、生命周期、清空策略和 pressure counters。
23. EntityQuery change filter 是 chunk 级优化，不是精确 gameplay event 语义。
24. Runtime Core 新增 system 必须先回答所属物理执行域 SystemGroup、所属 kernel lane、读写集合、结构变化权限、buffer 生命周期、query filter、Debugger counters；新增 SystemGroup 必须额外证明存在新的同步/结构变化/投影物理边界（`SYS-03` `PRF-07`）。
25. 业务代码评审必须引用 `UnityDOTS官方文档参考/主题/90-规则编号索引.md` 的具体规则编号，不能只引用抽象原则。
26. Runtime Core API 选型必须引用 `UnityDOTS官方文档参考/主题/20-GASRuntimeCore-API选型基线.md`；未评估 `NativeStream`、Chunk Component、Cleanup Component、EntityQuery bulk、system-associated entity、WeakObjectReference / UnityObjectRef 等候选 API 时，不得把既有实现承载视为目标态。
27. Runtime Core 每帧必须能解释 query/filter/allocator/dependency 的成本来源；这些成本不是 Debugger 后补指标，而是目标态 phase contract 的一部分。
28. DynamicBuffer 溢出、chunk fragmentation、shared component unique value、enableable wait、job scheduling overhead 都属于架构健康问题，不得被归类为普通优化项。
29. ExecutionCalculation 目标态不使用托管 delegate 或可变静态注册表；动态计算必须能被 Burst job、generated static switch 或经证明的粗粒度 FunctionPointer 承载。
30. 无头验收不删除表现链路；Cue / UI / VFX / SFX 仍从 Boundary outbox 派生，只是最终 side effect 可替换为结构化日志。
31. AutoChess deterministic 验收必须明确 world time / tick source；不得用 Editor frame delta 或首帧 Burst 编译数据判断 Runtime Core 性能。
32. 目标 Archetype 数量 < 10；不使用 tag component（纯标记无数据字段）—— gameplay tag/status 默认通过 `TagMaskComponent` / `TagStatusFlagsComponent` / enum bit field 表达，enableable 仅用于明确拥有状态且经 profile 证明的 skip 场景。
33. 每个 DynamicBuffer 必须有 `InternalBufferCapacity` 声明和 spill 监控；buffer 外部化是性能退化信号，不是"能用就行"。
34. 每种 Component 必须明确分类为 Data/Buffer/Enableable/Chunk/Cleanup 之一；禁止"ECS component"笼统称呼掩盖选型决策。
35. Frame Prepare（frame clock / allocator / dependency / query-lookup budget）是 Runtime Core 的前置基础设施，不是可选优化；hot path 禁止临时创建 EntityQuery，Lookup / TypeHandle 必须由 owner `ISystem` 在 `OnUpdate` 刷新并被 Debugger 计数。
36. Enableable toggle 只在明确拥有状态的 lane 执行：高频状态归 `GASCoreSimulationSystemGroup` 的 State lane，grant/revoke/destroy 归 `GASStructuralCommitSystemGroup`；Target Resolve / Effect Fan-In / Attribute Reduce-Apply / Gameplay Fact lane 对 enableable 只有只读访问；同步 enableable-filtered query 不得在 hot path 无评估使用。
37. Chunk Component 是性能优化，不替代 per-entity 状态正确性；使用 Chunk Component 的 phase 必须有 Debugger 一致性验证。
38. 禁止使用已废弃的 DOTS API（如 `IAspect`，deprecated since Entities 1.4.6）。所有 API 选型必须以项目 PackageCache 版本的非 deprecated API 为准；统一替代方案为直接 component 访问和 query 方法。目标态不保留 `IAspect`，新 Runtime 代码不得引入。参见 `CASE-13`。
39. Runtime Core job 内结构变化默认录制 ECB，并在 `GASStructuralCommitSystemGroup` 的明确 playback phase 合并执行；禁止从 Job 内部直接调用 `EntityManager`。`ExclusiveEntityTransaction` 仅限 secondary/streaming World 的窄口批量结构变化，不是 ECB 等价物，也不是通用 worker-thread `EntityManager` 替代（`PRF-21`）。
40. EntityQuery 创建必须通过 `SystemState.GetEntityQuery`，禁止使用 `EntityManager.CreateEntityQuery`（`PRF-33`）。通过 SystemState 创建的 query 能被安全系统追踪、参与 dependency 管理；直接 `EntityManager` query 无法被系统自动管理生命周期和依赖完成。
41. ASC Entity 批量创建必须使用预建 Archetype（`EntityManager.CreateArchetype`），禁止逐 Component 添加（`PRF-24`）。逐 Component 添加产生 N-1 个冗余中间 Archetype 永久存在，增加所有 EntityQuery 计算开销。
42. 同一游戏模式内所有 ASC Entity 默认具有相同 AttributeSet family 组件集合；不同角色“不使用某属性”优先通过默认值、tag requirement 或 effect requirement 表达，不通过移除属性 component 表达。
43. NativeContainer（含 `AllocatorManager.AllocatorHandle`）放在 `IComponentData` 上时，禁止对该 entity 调度 `IJobChunk`/`IJobEntity`（`PRF-34`）。主线程提取 handle 后作为 Job 参数传入。
44. `IJobEntity`/`IJobChunk` 中使用 `ComponentLookup`/`BufferLookup` 随机访问其他 entity 时，必须确保被访问 entity 集合与 job 直接遍历的 entity 集合无数据重叠，否则标记 `[NativeDisableParallelForRestriction]` 并附安全证明（`PRF-19`）。优先方案：owner-local buffer 替代跨 entity lookup（`PRF-06` `QRY-04`）。
45. Attribute 默认实现为 generated AttributeSet family，并按真实热路径/变更频率拆成 Current set 与 Base/Config set；不再默认“一属性一 component / 一属性一 system”。Current 高频写与 Base 低频写必须分离，避免高频写触发 Base 的 ChangeFilter 误触发。
46. 独立 per-attribute component 只允许作为有 profiler/query contract 证明的例外，且必须证明新增 component type、system/handle 成本和 archetype 变化仍低于收益。
47. Runtime assembly 不得依赖 `cfg.*`、`XLuban`、`SimpleJSON`、Luban managed row 或 JSON table reader；Runtime Core 只消费 generated ids、`GASDefinitionCatalogBlob` / Blob、unmanaged lookup、Generated Runtime Glue、component type 和 static switch。
48. 静态定义 Blob 必须从 Luban row、generated definition 或 Baker 输入构建；禁止从 prototype entity、runtime component 或 active effect state 反推静态 definition。
49. 生成链必须有单一 metadata context、Phase manifest、输出路径审计和 orphan `.g.cs` 清理机制；重复反射扫描和分散硬编码推断只能作为非目标态兼容债务。
50. Generated static lookup / calculation registry 必须 Burst 可读且具备明确生命周期；托管数组、managed dictionary、托管 delegate 和可变静态 registry 不得进入 Runtime Core hot path。
51. Baker 生成物必须是 stateless `Baker<TAuthoring>` 或显式 Baking System plan；静态 ECB helper 不能作为目标态 authoring / baking 边界。
52. `IJobChunk` 的 query 若包含 enableable component，`Execute` 必须在 `useEnabledMask == true` 时使用 `ChunkEntityEnumerator` 或 `EnabledMask`；`useEnabledMask == false` 时可走普通 `for` 快路径。若确认 query 永不含 enableable mask，必须显式断言 `useEnabledMask == false`（`PRF-22` `CASE-26`）。
53. 每个并行 Job 使用独立 ECB；多个并行 Job 禁止复用同一个 `EntityCommandBuffer` 实例，除非能证明 sortKey 域不重叠且回放顺序不影响确定性（`PRF-25`）。
54. Status / Buff / Debuff 类标记超过 3 个独立状态时，必须合并为 `TagMaskComponent` / `TagStatusFlagsComponent` / enum bit field；禁止每个 status 一个 tag component 或 enableable component（`PRF-03` `FSM-05`）。
55. Runtime Core 中同时包含只读配置字段和高频读写字段的数据结构必须拆分；使用 change filter、reactive projection 或 typed fact 监听时，禁止因 `ref` 访问只读字段导致 chunk 误标 changed（`PRF-26`）。
56. Runtime Core 目标态 SystemGroup 只表达物理执行域，默认固定为 `GASFramePrepareSystemGroup`、`GASCommandResolveSystemGroup`、`GASCoreSimulationSystemGroup`、`GASStructuralCommitSystemGroup`、`GASBoundaryProjectionSystemGroup`；Boundary/Target/FanIn/State/Attribute/Fact 是 lane，不默认建 group。
57. CoreSimulation 默认单帧数据流必须是有向无环图；`Gameplay Fact` 触发的新 GE 默认写 next-frame command seed。若业务必须同帧连锁，必须显式声明 bounded reaction pass、最大 pass count、cutoff reason 和 Debugger counters。
58. Luban / SourceGenerator 进入 Runtime Core 的默认形态是 `GASDefinitionCatalogBlob` + generated code->index lookup + Generated Runtime Glue；`GASGeneratedDefinitionBlobComponent<T>` 的 per-definition entity 只允许作为 baking output / bootstrap 收集入口，不作为 hot path lookup（`BLOB-01` `QRY-04`）。
59. Runtime-visible generated artifact 不得包含 `: ISystem`、`OnUpdate(ref SystemState)`、system registration、`CreateSystem(`、`AddSystemToUpdateList(`、`state.EntityManager`、ECB、`SystemAPI.Query`、`ComponentLookup` / `BufferLookup` owner 或 NativeContainer owner。除非标记 `MigrationProofOnly` 且绑定移除任务，否则视为目标态失败（`SYS-01` `SYS-03` `QRY-01` `QRY-04` `SC-01` `ECB-03` `NAT-03` `BUR-01`）。
60. SourceGenerator 只生成 definition / blob / lookup / Baker glue / query hint / validation report / static pure glue；Runtime Core lifecycle、query ownership、dependency ownership、allocator ownership、ECB ownership 和 NativeContainer ownership 必须由手写 ECS System 拥有。
61. Definition Catalog singleton 在 bootstrap / scene load 后不可写；Runtime system 只能只读获取 `BlobAssetReference<GASDefinitionCatalogBlob>` 并传入 job。singleton API 不完成依赖，因此禁止在 runtime tick 内写 `GASDefinitionCatalogComponent`。
62. `GASGeneratedDefinitionCatalogBuilder.BuildCatalog()` 或等价 `BlobBuilder` 入口只能属于 Baking / Bootstrap / initialization owner，并明确 runtime-created Blob 的 dispose owner；Runtime Core hot path 不调用 builder（`BLOB-02`）。
63. 含 `BlobArray` / `BlobString` / `BlobPtr` 的 definition 数据必须通过 index + `ref readonly` 访问；lookup API 禁止按值返回 Blob 元素。
64. Generated Runtime Glue 必须是静态纯函数 + unmanaged record：`AbilityDefinitionIndex -> AbilityActivationPlanRecord -> GECommandSeedRecord -> ResolvedModifierRecord`。禁止把 glue 实现成 singleton、manager、strategy object、runtime lifecycle system 或 hidden ECB/query。
65. Definition Catalog 的可变长数据默认使用 root `BlobArray` + `Start/Count` range 表达；Ability / GE definition 只保存 index、range、code 和 policy，不保存嵌套 runtime state。
66. 使用 `NativeStream` / `NativeList` 连接 Runtime lane 时，owner system 必须显式串联 JobHandle 并负责 dispose/rewind；ECS `Dependency` 不会自动追踪 NativeContainer 之间的数据流。
67. Application Shell 可以拥有面向业务的 Battle Runtime Adapter seam，但该 seam 不得成为 OOP gameplay 中间层。Adapter 对外 interface 只表达业务 runtime 动作；direct `EntityManager`、catalog lifetime、ASC lifecycle、observation reset、official diff 必须在 implementation 内按 owner 分类并可审计。
68. AutoChess headless runner、scene runner、Profiler pass 和 official diff pass 必须共享同一 validation evidence model；字符串 summary、Mermaid 图和中文日志只是导出格式，不是验收机器依据。
69. AutoChess unit / scenario / scale profile / validation expectation 的长期权威来源必须来自 Luban / SourceGenerator 生成物；`GameRoomFactory`、runner 常量、serialized fields 或 managed row array 只能作为短期 proof-only 输入。
70. ExecutionCalculation 业务公式必须进入 generated evaluator / static switch / batch path；ECS system 中硬编码 calculation code、GE code 或公式只能作为 proof-only，并必须提供重新选型触发条件。
71. CodeGen validation report 必须检查 generated lifecycle / ownership / random lookup / NativeContainer owner / structural change hits；只检查 forbidden dependency 或 naming debt 不足以证明生成链路达标。
72. GAS 概念设计必须先分类为 ECS 权威状态、frame-local record、Boundary 投影或 Definition 输入；未分类概念不得直接进入 Runtime Core 实现。
73. Ability 激活上下文是 frame-local record，不是 Ability entity 的跨帧状态，也不是 OOP action object。
74. GameplayEffect 的默认目标身份是 command/spec/delta 或 active slot；simple instant GE 不允许因“统一模型”默认创建 runtime GE entity。
75. Gameplay Fact 必须区分 CoreReactionFact 与 BoundaryObservationFact；Core reaction 默认写 next-frame command seed，同帧连锁必须声明 bounded reaction pass。
76. Thin Adapter 只翻译业务意图和导出观察结果；不得承载伤害、治疗、cost、cooldown、requirement、stack、period、target resolve 或 execution calculation。
77. Runtime Debugger 的最小价值是性能热点和 DOTS API 健康度归因；只输出字符串日志而没有 SystemGroup / lane / job / buffer / structural evidence 的 Debugger 不达标。
78. SourceGenerator 的性能价值来自 immutable catalog、generated lookup 和 static pure glue；任何 generated runtime lifecycle 都必须标记为 MigrationProofOnly 并绑定移除计划。
79. API health evidence 必须按 owner 分类后再参与验收：Runtime Core、Runtime Boundary、Debugger / Observation、Definition / Generation、Demo Adapter 至少五类必须分开输出。未分类的 `EntityManager`、query materialization、sync point、managed allocation、NativeContainer、ECB 或 singleton carrier 命中不能被写成 Core 性能结论，也不能被平均 tick、字符串日志或图表导出掩盖。
80. Runtime `Entity` 是 Core / Boundary implementation 的内部 identity，不是 Application Shell、Demo session、业务 report、UI、AI、Network 或 save/replay 的稳定 key。目标态外部 identity 必须是 opaque handle、battle unit id、report key、snapshot key 或 deterministic gameplay id。
81. Runtime Core system registration 的唯一 owner 是手写 schedule registry；SourceGenerator 不得自注册 system。generated artifact 缺失、类型不匹配或 assembly 不可用必须由 validation / bootstrap gate fail-fast，不能静默形成部分 Runtime。
82. Shell / Adapter capability 必须分级：command、snapshot、diagnostics、bootstrap、definition 至少五类不得共享同一个 public ECS 句柄出口；外部业务 API 不得返回或 out `World`、`EntityManager`、runtime singleton `Entity`、`EntityQuery` 或可写 `DynamicBuffer`。
83. Editor watcher、Debugger、Replay、Official diff 只能通过 diagnostics / snapshot capability 读取 evidence；它们不得复用 command capability 的可写句柄，也不得把 diagnostics gather key 作为业务稳定 identity。
84. Runtime access 聚合实现不能作为目标态验收接口；bootstrap、catalog/definition、command write、snapshot read、diagnostics/export、fixed tick runner 和 dependency drain 必须各自有 owner 分类、证据字段和成本归因。
85. 新划分设计必须通过 DOTS Official Review Gate：任何 Runtime Core 任务在实现前必须完成数据性质分类、候选 API 评估、采用/拒绝理由、官方规则编号、重选型触发条件和 proof-only 退出条件。
86. Runtime Core hot path 中出现 managed component、managed shared component、managed config row、JSON reader、`Dictionary`、托管 delegate、`ScriptableObject` 或 SystemBase/OOP manager 中间层时，默认判定目标态失败。
87. 性能红线不是后续优化项：entity churn、分散结构变化、隐藏 generated lifecycle、全局 singleton fan-in、无证明 random lookup 写、无容量 DynamicBuffer、无 owner NativeContainer、Debugger 托管日志污染，均必须在设计阶段拒绝。
88. 默认业务编辑对象是 Ability Package / Effect Package 等业务能力包，不是单张 Excel row；Raw Table 只能作为高级维护入口。
89. Editor 配置链只能构建 Business Authoring Session、Definition Draft Graph、row diff、validation snapshot 和 Runtime trace preview；不得成为 Runtime definition source 或 gameplay state owner。
90. Luban rows / schema / stable id 仍是配置长期权威；任何 Editor draft、ScriptableObject authoring asset 或窗口状态进入 Runtime 前都必须投影为 Luban row 并通过 SourceGenerator validation。
91. SourceGenerator 对业务模板的响应只能是 Blob / lookup / pure glue / validation / Editor binding metadata；不得因为模板化编辑而生成 lifecycle system、hidden query 或 hidden ECB。
92. 策划默认配置路径不得要求手写 raw protocol 字符串、offset raw columns 或裸 ID 分隔列表；这些只能出现在 Raw Table Advanced Mode。
93. 配置工具必须提供业务能力包级 Impact Analysis 和 Publish Validation Snapshot；修改 Ability / GE / Cue / Tag / Attribute 时必须能解释影响的业务包、单位、场景、规模配置和 validation expectation。
94. Runtime Trace Preview 是 Editor / CI 诊断证据，只能从 Luban row projection、generated catalog metadata 和 pure glue 推导；不得反向成为 Runtime Core 输入或 gameplay 决策源。
95. Internal ECS identity resolver 只能是 Boundary implementation 的私有细节，不是可复用中间层；业务 report、UI、AI、Network、Replay 和 Demo session 必须消费 opaque handle、report key、snapshot key 或 deterministic gameplay id。
96. 平衡调参能力是配置链验收项，不是 UI 优化项；冷却、消耗、等级、公式、DOT tick、stack、overflow policy 必须能在业务包内聚合预览并关联 Runtime record。
97. Business Template Catalog 必须由 Luban schema / SourceGenerator metadata / Editor Binding 驱动；硬编码 UI 模板、私有字段或不可生成协议不得作为目标态模板来源。
98. Business Package Change Set 是配置评审单元；没有 row diff、reference graph、impact analysis、runtime trace preview 和 review gate summary 的配置变更不得视为可发布。
99. Config Reference Graph 必须从 normalized rows / generated metadata 构建，禁止从 live Runtime World active state 反推静态配置引用。
100. Scenario Validation Binding 必须把业务包连接到 Unit、Scenario、Scale profile 和 validation expectation；配置发布不得只依赖人工点击或 demo runner 常量。
101. Generated Editor Binding 是 Editor 默认字段、choice source、引用类型、diagnostics code 和 raw protocol 映射的权威；Editor 不得复制 SourceGenerator 协议推断逻辑。
102. AutoChess Acceptance Ability Sample 是 AutoChess 配置验收的最小业务单元；每个样例必须包含 BusinessPackage、row projection、Config Reference Graph、Runtime Trace Preview、Scenario Validation Binding 和 AcceptanceAssertions，禁止只以 runner 常量或 C# test 私有数据作为验收输入。
103. 新增能力必须先进入 Ability Addition Workflow 三档分类：Configuration-Only Ability、Generated Glue Extension、Runtime Semantic Extension；未分类不得创建发布单元。
104. Configuration-Only Ability 必须做到程序 0 代码；数值、冷却、消耗、Duration、Period、Stack、Cue、Unit 绑定、Scenario 和 ValidationExpectation 变化不得触发 Runtime Core 或 SourceGenerator 代码修改。
105. Generated Glue Extension 只能扩展 Luban schema metadata、SourceGenerator pure glue、Generated Editor Binding、target rule / requirement / magnitude evaluator 和 validation rules；不得生成 Runtime lifecycle system、hidden query、hidden ECB、`EntityManager` write 或 NativeContainer owner。
106. Runtime Semantic Extension 必须先通过 DOTS Official Review Gate，明确 lane、store、carrier、phase、query contract、allocator owner、structural policy、Burst / managed 边界和 evidence model，再允许改 Runtime Core。
107. Impact-Scoped Validation 是新增能力发布的默认验证选择器；不得用“全量 runner 能跑”替代影响分析，也不得省略受影响 scenario / scale profile / validation expectation 的解释。
108. Authoring / Generation Control Plane 只能存在于 Editor、CI 和 Definition & Generation 侧；它负责业务表达、row projection、生成元数据、影响分析和发布证据，不得成为 Runtime Core OOP 中间层或 gameplay state owner。
109. 任意新增或修改能力必须先输出 Ability Configuration Analysis Report；该报告至少覆盖业务意图、激活、目标、效果拆解、数值公式、Requirement、Duration / Period / Stack、表现绑定、row projection、trace、impact 和发布证据。
110. Definition Row Projection Plan 必须是 Business Package 到 Luban rows 的机器可读中间产物；raw protocol mapping 只允许存在于 projection 过程，不允许成为策划默认输入。
111. API health 扫描命中必须先分类为 executable hot path、Boundary / Presentation、Debugger / Observation、Definition / Generation、Demo Adapter、validation text 或归档文本；只有分类后的可执行 owner 命中才能参与 Runtime Core 合规判定。字符串报告、Mermaid 导出、中文 summary 或文档命中不得被当作 Runtime Core 依赖证据，也不得反过来掩盖真实 hot path 命中。
112. Shell / Adapter capability 必须按 timing domain 和权限拆分：bootstrap、command write、snapshot read、diagnostics/export、fixed tick runner、dependency drain、definition/catalog lifetime 不得共用同一个可扩散 ECS handle facade。dependency drain / job completion capability 只能属于 runner sync 或 debugger measurement，不得作为业务 Shell API 或 Core 性能证明。
113. `ToEntityArray`、`EntityManager.CreateEntityQuery`、singleton fallback、manual sync 和 query materialization 只有在 owner 已分类、频率已证明、counter 已进入 Debugger 后才可作为 Boundary / Debugger / low-frequency fallback 保留；未分类命中默认不能参与 Runtime Core 验收。
114. Burst 和 `IJob` 不是 scale-ready 证明。高基数 gameplay 数据默认需要 `IJobChunk` / `IJobParallelFor` / owner-local batch pass；serial `IJob` 只能用于 bounded merge、bootstrap、diagnostics 或明确低规模 owner，并必须声明 reselect trigger、entity/command upper bound 和 Debugger counter。
115. Generated runtime artifact 中的 lifecycle system、serial job、random lookup、ECB、NativeContainer owner 或 structural owner 即使已被 validation report 分类，也只能作为 `MigrationProofOnly`；release-ready SourceGenerator mode 必须让这些 hit 归零或由 hand-written Runtime Core owner 明确接管。
116. `NativeStream` 正向使用必须同时满足 allocator owner、segment budget、dispose/rewind JobHandle 链和 deterministic merge 规则。只出现 `NativeStream` 或 `Allocator.TempJob` 不能证明 fan-in 达标；没有排序/merge policy 和 Debugger segment/merge cost evidence 时仍是 proof-only。
117. GAS 官方概念映射必须保留 Ability lifecycle、GameplayEffect definition、GameplayEffect spec、Attribute / AttributeSet、GameplayTag taxonomy、GameplayCue parameters、AbilityTask semantic mapping 和 ASC binding；业务包短路径不得删除这些语义。
118. `Ability Package / Effect Package` 只是 Editor / Authoring 聚合，不是官方 Ability、GameplayEffect 或 ASC 的 Runtime 替代物；进入 Runtime 前必须投影出 `AbilityLifecycleContract`、`GameplayEffectSpecShape`、`GameplayTagTaxonomy`、`CueParameterContract` 和 `ASCBindingContract`。
119. Ability lifecycle 必须显式表达 grant、can activate、activate、commit、cancel、block、end、failure reason 和 trace shape；只保存 Ability row 或模板参数不能视为能力语义闭合。
120. GameplayEffect definition 与 GameplayEffect spec 必须分离。Definition 进入 immutable catalog / Blob；runtime spec 只能表现为 frame-local command / modifier record、context record 或 active effect slot seed，不得混同为 managed GE object。
121. AbilityTask 不作为 Runtime OOP 类型进入目标态。wait、target data、async event、animation completion、tag / attribute watch 等语义必须映射到 ECS target lane、async state slot、typed fact、Boundary command 或 bounded reaction pass。
122. GameplayTag 必须输出 taxonomy 和 query evaluator；activation required / blocked、cancel / block ability、application / ongoing / removal requirement、immunity、cue route、gameplay event 不得退化成同一种裸 tag 引用。
123. GameplayCue 必须保留 cue tag、cue event、source / target context、magnitude snapshot、presentation binding 和 trace id；Cue 参数只能进入 Boundary / Presentation / headless marker，不得写 Core gameplay state。
124. ASC binding 必须能从 Unit / Scenario / GE grant 反查 AttributeSet family、owned tags、granted abilities、initial active effects 和 install / cleanup policy；Demo 常量或手写 bootstrap 不能替代长期配置权威。
125. 任何 AbilityTask-like、prediction-like、replication-like 或跨帧异步能力需求都不能默认归为 Configuration-Only Ability；必须先证明已有 ECS lane / store / fact / Boundary 承载，否则升级为 Runtime Semantic Extension。
126. DOTS Official Review Gate 必须同时记录 GAS 官方概念缺口和 Unity DOTS API 选型。只说“符合 GAS 概念”或只说“符合 ECS 性能”都不足以放行 Runtime Semantic Extension。
127. Debugger evidence 必须区分 Contract / Plan、Runtime Counter、Official Capture、Validation Evidence 和 Derived Export；contract 计数、字符串 summary、图表导出或 disabled official tool 状态都不能单独证明结构变化收口或 Core 性能达标。
128. `MigrationProofOnly` 不是完成状态；只有 carrier / lifecycle / query / ECB / NativeContainer owner 已迁入手写 Runtime Core owner 或 pure generated glue，并具备 Runtime Counter、Official Capture、Validation Evidence 和 reselect trigger，才允许退出迁移证明。
129. Singleton DynamicBuffer fan-in 默认只能是 proof / migration carrier；作为 scale-ready 例外时必须证明数据上限、owner 分类、deterministic merge、buffer spill、dependency chain、battle hash 稳定和 Debugger merge cost。
130. 任何“运行通过”“无 blocking error”“平均耗时达标”都不能替代 owner-locality 证明；Runtime Core、Runtime Boundary、Debugger / Observation、Definition / Generation、Demo Adapter 的成本和证据必须分开验收。
131. 文档体系本身也是架构契约：当前事实、目标态 Spec、任务树和短期进度必须有唯一 owner。相近主题应合并，过时架构描述应降权或归档；不得为了渐进式披露制造第二份事实正文或把当前实现分析混入目标态 Spec。
