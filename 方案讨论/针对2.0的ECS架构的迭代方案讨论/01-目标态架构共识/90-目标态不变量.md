# EX-GAS Runtime v1 目标态不变量

## 结论

本页是跨专题冲突时的最终裁决表。专题 Spec 可以增加细节，不能放宽这些不变量；需要改变时必须先立 ADR/设计裁决，再同步目标态、任务树和验收。

## A. 架构与权威

- `ARC-01`：Gameplay 权威只存在于 Layer 3 ECS Runtime Core。
- `ARC-02`：ASC Entity 是 Ability、Effect、Attribute、Tag 与 pending work 的唯一聚合根。
- `ARC-03`：Ability、Activation、Continuation、Subscription、ActiveEffect 和 EffectSpec 在 v1 不作为权威 Entity。
- `ARC-04`：Projectile/Aura/Zone 等派生 Entity 不得镜像或延长 Activation/ActiveEffect 权威。
- `ARC-05`：Definition/Catalog/Layout 在 Session 内不可变，运行中不热迁移存活 ASC。
- `ARC-06`：v1 不保留旧/新 Runtime selector、feature flag、fallback 或双权威。
- `ARC-07`：一个 World 同时只有一个 active GAS Session tick domain；一个 Session 可以包含多个稳定 BattleInstance，单战局终局不得误停其他实例。

## B. 调度与时间

- `TIM-01`：GAS 使用 FixedStep，`GasFixedTickSystemGroup` 是主 FixedStep 直接子组并在主 Physics 后更新。
- `TIM-02`：全局 GAS 不挂 `AfterPhysicsSystemGroup`，避免多 PhysicsWorld 复制更新。
- `TIM-03`：一个 RenderFrame 可以有 `0..N` 个 SimulationTick；两者术语不得混用。
- `TIM-04`：duration、period、cooldown、wake/due time 使用整数 tick。
- `TIM-05`：tick rate 在 Session 启动后不可变并进入 session/content hash。
- `TIM-06`：一个 `GasTickKernelSystem` 拥有本 tick query、scratch、完整 Job DAG 和最终 dependency。
- `TIM-07`：逻辑 stage 默认是 Job/pure evaluator，不升格为多个 `ComponentSystemGroup`。
- `TIM-08`：独立 World/Runner 必须更新完整 FixedStep、标准 EndFixed 和 Drain，禁止直接更新子组/Kernel。
- `TIM-09`：ScaleProfile 必须限制 `MaxFixedTicksPerBatch/MaximumDeltaTime`；Headless 不得把整场长模拟塞入一次 outer TickBatch。
- `TIM-10`：tick-start 已到期的 PeriodDue 在 DueTick 同 tick；post-apply/overflow/reaction 动态 child 默认 T+1，二者不得混写。

## C. 内存、Job 与结构变化

- `MEM-01`：tick scratch 使用 `SystemState.WorldUpdateAllocator`；禁止自定义 FrameArena/manual rewind。
- `MEM-02`：临时 NativeContainer 不跨 System/tick 保存，长期状态必须进入 ECS authority/pending data。
- `JOB-01`：同一 ASC 每 tick 只有一个逻辑 mutation lane；不同 ASC 可并行。
- `JOB-02`：禁止随机跨 ASC 写入或解除安全限制掩盖 owner 冲突。
- `JOB-03`：正常 stage 之间不得 `Complete()`；`CompleteAllTrackedJobs()` 不得成为正常 tick fence。
- `JOB-04`：fan-in 结果由语义 canonical key 决定，不依赖 Job/chunk 完成顺序。
- `JOB-05`：权威 mutation 依赖串联为 AscOwnerCommandWave → AscTargetStateWave；OwnerWave 不观察本 tick incoming target Effect。
- `JOB-06`：Gather 必须在 Owner plan/target expansion 写 variable scratch 前，以 sealed/due count + bake maxima checked 产生并 provision `PlanExpandScratchEnvelopeToken`；逻辑超限使 Plan/Expand no-op，再由唯一 infrastructure admission 提升为失败。Admission 只验证 token并预留下游/持久容量；下游 Job预排在同一 DAG并读取 AdmissionResult，失败时整个 tick gameplay权威零写。FaultLatchJob 写 Detected/sealed subset；outer FaultClose 与 CommandPort accept 在同一 gate 线性化，以 IngressClosed accepted-outstanding RequestSequence first/last/count/hash 覆盖 close 前全部未终结请求，不向未准入 outbox 写逐请求回执。
- `JOB-07`：canonical key 的 SemanticPhaseOrdinal/WorkClassOrdinal 来自 schema/catalog hash，不得使用物理 Job/Profiler lane或 batch切分。
- `JOB-08`：CommandPort accept 在 `SessionIngressGate` 分配单调 `RequestSequence` 并把完整 record写入 Boundary 持久 `BoundaryIngressJournal` 后才成功；重复 RequestId复用原 sequence。必装 pre-Fixed `GasCommandIngressSystem` 是唯一 ECS inbox writer并原样透传 sequence；Kernel 读 DynamicBuffer 期间禁止以 prefix/tail 不同 range 为由并发 append。
- `STR-01`：结构变化使用标准 `EndFixedStepSimulationEntityCommandBufferSystem`。
- `STR-02`：EndFixed 创建/销毁产生的结构结果最早下一 SimulationTick 被 Kernel 查询。
- `STR-03`：SpawnBatch setup EndFixed只创建 Pending ASC/Registry；下一 FixedStep由同一 Kernel SpawnFinalize maintenance mode在 shadow 完成/preview全批 `SpawnInitializationTransaction`（Attribute/Tag/Grant/闭世界 self-initial-effect）并完成容量准入，才 no-fail 发布权威/initial fact/Cue/Ready；该 update不计 gameplay Tick且没有 post-EndFixed Ready writer。

## D. Identity 与 Slab

- `ID-01`：长期 handle 包含 `SimulationEpoch + OwnerAscHandle(AscStableId, AscGeneration) + SlotIndex + SlotGeneration`；ASC lifecycle generation 与 slot generation分别校验。
- `ID-02`：GrantedAbility、Activation、Continuation、Subscription、ActiveEffect 使用强类型 handle；无类型 carrier 额外校验 HandleKind。
- `ID-03`：slab 使用 tombstone/free-list，禁止 RemoveAt、SwapBack 与存活期 compact。
- `ID-04`：Generation 只在实际回收复用时递增，回绕为确定性 fault。
- `ID-05`：terminal fact、子记录、订阅与队列引用完成交接前不得回收槽。
- `ID-06`：跨 tick work 复制冻结 payload，不从 stale/reused slot 重建。
- `ID-07`：Owner 与 Avatar 分离；Avatar 重绑不销毁 ASC。
- `ID-08`：raw Entity 不越过 Runtime Boundary，public liveness 不使用 `EntityManager.Exists`。
- `ID-09`：Target identity、Avatar binding、spatial sample 与 TargetLifePolicy 是正交轴；Self 只能由显式 SelfTarget rule产生，禁止失效目标 fallback-to-owner。

## E. Ability 与 Continuation

- `ABL-01`：生命周期为 `Definition -> GrantedAbilitySlot -> ActivationSlot`。
- `ABL-02`：一个 grant 可按实例策略拥有 N 个 Activation；一个 Activation 可拥有 N 个 Continuation/Subscription。
- `ABL-03`：CanActivate 与延迟 CommitCheck/CommitExecute 分离；Commit 必须重新检查 cost/cooldown。
- `ABL-04`：owner-local `CostMutationContract`、`CooldownGateContract`、Committed flag 与 activation state 原子提交；Cost 写同一 Attribute 权威，Cooldown 写 ASC-owned gate，失败无部分写入。
- `ABL-05`：Commit 最多成功一次；Commit/Cancel/End/late wake 具有明确幂等或 reject 语义。
- `ABL-06`：Activation 只拥有 activation-owned Tag/Block/Cue/Continuation；普通 emitted application ref 仅作审计，除显式 `RemoveOnActivationEnd` 外不随 End 撤销。
- `ABL-07`：Activation 结束清理全部 Continuation/Subscription；外部订阅投递与取消验证双 Generation。
- `ABL-08`：CommitPlan 先完整预检再 no-fail 原子提交；Commit→Cancel 保留 cost/cooldown/committed work，Cancel/End→Commit typed reject。
- `ABL-09`：Wait 的 sample/register 在 observed ASC writer 内线性化；Level 可立即 completion，但所有 Continuation resume 最早 T+1，跨 ASC 注册有 ack/cancel 状态机。
- `ABL-10`：`CooldownGateSlot` 归 source ASC 且独立于 Activation/ActiveEffect；Commit→Cancel/End/死亡不删除 gate，tick-start `EndTick <= CurrentTick` 释放及 Tag contribution 撤销先于当 Tick新请求。
- `ABL-11`：v1 Cooldown 冲突/移除语义固定为 `RejectWhileActive + ExpireOnly`；Cost/Cooldown GE-like authoring 不可表达的 stack/refresh/period/execution/dispel 必须 bake fail。

## F. GameplayEffect、Tag 与 Attribute

- `GE-01`：生命周期为 `Definition -> EffectApplicationSpec -> ActiveEffectSlot`；Instant 不创建 ActiveEffectSlot。
- `GE-02`：EffectApplicationId 独立于 ActiveEffectHandle；stack 合并和 Instant 仍保留独立应用身份。
- `GE-02A`：Commit前TargetResolve只有 tick-local SpecDraftToken 与 canonical ProgramNode/Spec/PlannedApplication ordinal；成功Owner Commit的同一线性化点仅由 `(Epoch, SourceAscHandle, canonical CommitSequence, ProgramNodeOrdinal, SpecOrdinal[, PlannedApplicationOrdinal])` 提升正式 EffectSpecId/EffectApplicationId 并写owner audit ref，SourceSpecProjection随后密封Spec/Capture；SpecDraftToken/worker/scratch index不进入正式身份或 semantic hash，失败plan无可观察身份或ref。
- `GE-03`：Active、Inhibited、Removing/Tombstone 语义不同；Inhibited 保留槽、时间、stack 与 context。
- `GE-04`：Application/Ongoing/Removal/Immunity requirements 保持独立 phase，不得压平。
- `GE-05`：stack/period/overflow/source key 与 remove provenance 必须确定且可精确撤销。
- `GE-06`：committed-work-wins：source 后续死亡不撤回已 Commit operation；target 在 application线性化点按 life/binding/requirement/immunity独立接受或拒绝。
- `GE-07`：stack payload、duration refresh、period reset、execute-on-apply、expiry/final-period、inhibit/resume、missed-period 与 Cue policy 是独立生成契约。
- `GE-08`：Granted Ability removal公开为 CancelImmediately、RemoveWhenAllActivationsEnd、LeaveGranted；LeaveGranted 脱离 cleanup ownership但保持 grant Live。
- `TAG-01`：Tag authority 为 Catalog-indexed `ExactCount + InclusiveCount`；bitset 只是派生缓存。
- `TAG-02`：Tag underflow、overflow、重复撤销为 fault；每个贡献有稳定 source key。
- `ATT-01`：Attribute authority 为 Session fixed-layout buffer 的 Base/Current/Revision，不存在 per-attribute component mirror。
- `ATT-02`：Aggregator 保留 channel、op、qualifier、contributor、稳定 order 与 override tie-breaker。
- `ATT-03`：ECS buffer change version 不代替具体 Attribute/Tag dirty/revision。
- `ATT-04`：dense backend 不达标时通过 ADR 整体替换，release runtime 不并存 dense/sparse 双后端。
- `ATT-05`：Death 只由首次 `old > 0 && unclamped <= 0` crossing产生并冻结 killer/overkill provenance；后续 AliveOnly reject不得贡献 damage/assist。

## G. Capture 与稳定化

- `CAP-01`：每个 capture 声明 Source/Target、Snapshot/Live、phase、missing policy 与 `CaptureProjectionContract`。
- `CAP-02`：Projection contract 是闭世界 API；未声明的 view/filter/ignore/contribution 查询必须 bake fail。
- `CAP-03`：ScalarSnapshot 只有在全部 contributor/qualifier/tag/filter/ignore 输入已冻结且后续 view 不会升级时合法。
- `CAP-04`：否则保存可重演的规范化 AggregatorSnapshot，保留 stable contribution order/provenance。
- `CAP-05`：Live Capture 以 attribute revision 驱动；跨 ASC 必须确定序通知，未实现时 bake fail。
- `CAP-06`：PhaseSample 不得命名或解释为 UE Live Capture。
- `CAP-07`：Source Snapshot 在成功 Commit 后由 `SourceSpecProjection` 冻结；Target capture/requirement/immunity在每条 target application前按 canonical read-your-writes求值。
- `CAP-08`：跨 ASC Live revision 在 T 产生 destination-grouped dirty work，最早 T+1更新；consumer identity、source-gone、cycle/budget与两端 Generation缺一即 bake fail。
- `STB-01`：Tag/ongoing/inhibition/contribution/aggregator 在单目标 transaction 内达到稳定点后才发 final fact/Cue。
- `STB-02`：生成期保守检查有符号依赖图；运行时仍做重复 state/budget 检测。
- `STB-03`：无固定点产生 fatal StabilizationFault，禁止静默 pass cap 和半稳定继续。

## H. Reaction 与因果

- `RCT-01`：v1 采用 stable-state deferred reaction，不承诺 UE 同步 call-stack 时序。
- `RCT-02`：GameplayEvent、OwnedTag trigger、外部 Continuation wake 和跨 ASC reaction 默认下一 tick。
- `RCT-03`：每经过一条公开 reaction 边至少增加一个 tick；payload 在 emit 时冻结。
- `RCT-04`：本 tick Apply 后 fact 不重新进入本 tick fan-in。
- `RCT-05`：same-tick DirectEffectProgram 必须闭合、可完全展开、有限、静态有界且只读 pre-apply 输入。
- `RCT-06`：requirement/immunity/stack/commit/clamp/inhibition 等正确性逻辑是 kernel invariant，不通过公开 reaction 延迟。
- `RCT-07`：CausalityId 用于排序、追踪与环检测，不是 PredictionId。
- `RCT-08`：reaction recipient 由 catalog-hashed kind priority、tag depth、stable recipient/definition/registration/wake ordinal形成全序。

## I. Boundary、Cue 与观察

- `BND-01`：Core final fact 恰写一个 scoped `ICleanupBufferElementData` outbox：ASC-scope→所属 ASC，BattleInstance/Session-scope→唯一 Session；任一 owner Destroy 后终态 facts 不丢。
- `BND-02`：每 Session 恰有一个 managed Drain；Headless 也必须安装。
- `BND-03`：`BoundaryDrainState` 只持久冻结 physical owner identity、不重置的 NextOwnerSequence 与 InFlight BatchId/Watermark；Session owner 不伪造唯一 Battle。managed staging 幂等接管成功后只清 `EventId.OwnerSequence <= InFlightWatermark`，late tail 保留，失败时 ECS事实与 retry identity 原样保留。
- `BND-04`：所有 Cue/UI/Replay/Debugger consumer 只读同一 immutable batch/ring。
- `BND-05`：Core 不维护 per-consumer cursor，consumer 不直接读取或清理 ECS outbox。
- `BND-06`：`BoundaryEventId=(Epoch, PhysicalOwnerKind/Id/Generation, OwnerSequence)` 与 `CueLifecycleKey=(Epoch, ActiveEffectHandle, ActiveCycleOrdinal, CueDefinitionOrdinal)` 分离；前者负责全局交付/去重，后者只配对 active cycle，Executed 另用 Application/PeriodExecution identity。
- `BND-07`：overflow 明确报告范围和 policy，永不静默覆盖；表现 reconcile 不反写 Core。
- `BND-08`：无头只省略资源，不省略 Cue marker、Drain、Replay 与 diagnostics 路径。
- `BND-09`：正常 shell removal 由下一 Kernel cleanup prepass记录当 tick EndFixed；post-Fixed Drain不创建跨 batch ECB，无下一 tick时只在 FinalDrain/producer完成后teardown。
- `BND-10`：BattleOutcome 在 `FactPlane=Gameplay` facts完成 staging接管后冻结；最终 ValidationResult 在 teardown audit后返回，`FactPlane=TeardownAudit` facts不改变 winner/BattleHash，Result后零新事实。FactPlane 与 Asc/Battle/Session ScopeKind 正交。
- `BND-11`：Cue lifecycle key含 Epoch、ActiveEffectHandle、ActiveCycleOrdinal、CueDefinitionOrdinal；Executed与 BoundaryEventId分别使用 execution identity和交付 identity。

## J. Definition、Prediction 与验证

- `GEN-01`：SourceGenerator 只生成 immutable catalog/schema/index、pure evaluator、validation 和 Editor metadata。
- `GEN-02`：generated artifact 不拥有 System lifecycle、query、ECB、EntityManager write、allocator 或 NativeContainer lifetime。
- `GEN-03`：Catalog 预解析 layout/tag/capture/program/dependency 与规模信息，hot path 不反查 managed row/JSON/Dictionary。
- `GEN-04`：Luban 是 authoring语义唯一权威，Runtime Blob是运行快照；SourceGenerator只生成glue，重复/隐藏override与非法enum/range必须 bake fail。
- `NET-01`：v1 不实现复制、预测、rollback、ack/reject/catch-up。
- `NET-02`：PredictionKey、predictive flags、prediction journal/undo/ack 字段从 schema/API 删除，不保留零值占位。
- `VAL-01`：语义测试覆盖 handle、并发 Activation/Continuation、Commit、Effect、Capture、Tag、Aggregator、Cue 与 Reaction。
- `VAL-02`：完整运行测试覆盖 FixedStep/Physics/EndFixed/Drain、Destroy terminal facts、Scene/Headless/AutoChess 同路。
- `VAL-03`：ScaleProfile 分别覆盖 replicated groups、hot-target fan-in、period burst、mass-death teardown、Boundary retry、wait fanout与 cross-ASC live dirty。
- `VAL-04`：同 input/session/content hash 重跑的 command trace、slot lifecycle、最终状态、fact/Cue 顺序和 battle hash 一致。
- `VAL-05`：semantic hash排除 raw Entity、RenderFrame、wall clock、transport batch切分、Profiler/Journaling与表现截断；不同 bounded TickBatch切分必须同 hash。
- `DOC-01`：00/01/02/04 分别只维护当前事实、目标规范、任务、短交接；不得互相冒充完成证明。
