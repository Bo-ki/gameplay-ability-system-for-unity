# 文档治理与目标态共识 - 官方文档查缺补漏与流程闭环

## 父节点

[T0 文档治理与目标态共识](README.md)

## 节点定位

本支线负责维护 Unity DOTS 官方文档参考进入当前路线的执行闭环。它不直接决定 Runtime Core 的业务实现，而是保证 `UnityDOTS官方文档参考` 下的单主题文档能被任务树、行动报告、迭代摘要、当前事实和验收流程实际消费。

## 当前问题

1. 官方文档深读已经形成多个 Spec，但如果缺少覆盖矩阵，后续 Agent 仍难判断哪些官方主题已经覆盖。
2. 行动报告此前要求 API 选型和官方案例对照，但缺少“官方文档覆盖检查”的稳定字段。
3. 迭代摘要反哺流程需要明确官方文档缺口如何进入 `UnityDOTS官方文档参考` 对应主题，再反哺目标态业务 Spec 和任务树。
4. 旧聚合文档已经被拆成单主题文档；后续任务只能引用顶层入口和具体主题，不能再引用旧文件组。
5. Unity 6000.3.14f1 升级后新增 Unity Physics 与 Entities Graphics 包，官方参考体系需要补齐物理输入层和表现渲染边界层。

## 历史方案参考

历史方案参考只提供文档表达和治理思路。本支线的第一性依据是当前项目锁定的 Unity PackageCache 官方文档版本，而不是历史方案中的旧版本诊断。

## 支线目标

1. 建立官方文档参考体系主题 owner。
2. 建立官方文档覆盖矩阵 owner。
3. 建立 `ODF-*` 官方文档流程规则。
4. 把官方文档覆盖检查写入行动报告、任务树质量检查和迭代摘要反哺流程。
5. 确保后续 Runtime Core / Debugger / Luban / AutoChess 任务能先读主题入口，再引用 `ODF-*` 规则并输出验收指标。

## 当前状态

已完成。`UnityDOTS官方文档参考/主题/21-官方文档覆盖与流程闭环.md` 已新增并接入文档治理和任务树；`UnityDOTS官方文档参考` 主题入口已建立。PackageCache hash 路径、manifest / lock / actual 版本差异、Managed boundary、Baking world、EntityPrefabReference、Burst AOT 和 allocator aliasing 已形成 `ODF-09..14`。Unity Physics / Entities Graphics 新包覆盖已补入参考体系并形成 `ODF-15..18`。全部 ~175 个 PackageCache 文档已读完，CASE 47 / PRF 34 / FSM 6 / SEL 5 / ODF 18 规则体系建立。完整历史已归档到 [已完成文档校准日志](已完成文档校准日志.md)。

## 非目标

1. 不修改 Runtime 代码。
2. 不修改 `Library/PackageCache`。
3. 不把在线最新 DOTS 文档直接覆盖当前 `1.4.6` 项目版本。

## 执行细则

1. 新官方文档结论先通过 `UnityDOTS官方文档参考` 判断主题归属。
2. 新官方文档结论再进入 `UnityDOTS官方文档参考` 对应主题。
3. 改变 API 选型时同步 `UnityDOTS官方文档参考/主题/20-GASRuntimeCore-API选型基线.md` 和 `UnityDOTS官方文档参考/主题/90-规则编号索引.md`。
4. 改变官方案例写法时同步 `17` 和 `CASE-*`。
5. 改变执行流程时同步对应主题文件夹内的治理规范。
6. 改变任务领取上下文时同步 `02-主线任务树` 和 `04-当前进度状态/当前窗口.md`。

## 验收门槛

1. 当前路线根 README 索引 `UnityDOTS官方文档参考`，目标态 README 只作为引用方。
2. `Agent行动报告规范.md` 包含“官方文档覆盖检查”。
3. `04-当前进度状态/迭代摘要反哺流程规范.md` 包含官方文档缺口反哺流程。
4. `02-主线任务树/README.md` 登记 `AM-1E`。
5. `04-当前进度状态/当前窗口.md` 要求后续任务读取 `UnityDOTS官方文档参考/主题/21-官方文档覆盖与流程闭环.md` 并引用 `ODF-*`。
6. `UnityDOTS官方文档参考` 主题入口和 `UnityDOTS官方文档参考/主题/21-官方文档覆盖与流程闭环.md` 覆盖矩阵必须记录真实 PackageCache hash 路径和 package 版本，不再使用不存在的 `@version` 路径作为本地证据。
7. 行动报告、AutoChess summary、Debugger summary 和 Luban 生成报告必须能承接 `ODF-09..18` 的字段或明确不相关理由。
