# 目标态不变量

1. GAS Runtime Core 权威只在 ECS 数据中。
2. 外部写入只通过 request entity 或等价 command data。
3. 外部观察只通过 mirror、outbox、replay、debugger、read model。
4. Definition & Generation Layer 不携带 runtime state。
5. Runtime state 不反查 managed authoring config。
6. Cue / Presentation 不决定 gameplay。
7. System 调度显式、可测试、可追溯。
8. Editor authoring 不引入 runtime source dependency。
9. Generated pipeline 只强化已经稳定的 contract，不发明新语义。
10. UE GAS、tranek、方案1-15 都是参考来源，不替代当前代码事实和 Unity ECS 第一性约束。
11. 性能优化不能提前吞掉 GAS 语义问题。
12. Debug / Replay 是事实记录，不是状态权威。
13. 性能结论必须标明采样口径；默认只接受 `ecsRuntimeTickOnly` 作为 ECS Runtime tick 讨论基础。
14. 高频业务 reaction 应使用 typed facts / cursor / stable ECS state。
15. Simple instant GE 可以绕过 request entity / 临时 GE instance 热路径，但不能绕过 GAS 事实语义。
16. ECB playback 是结构变化成本，也是同批 GE apply 的语义可见性屏障。
17. Runtime Core Debugger 是运行健康事实流，不能反向驱动 GAS Runtime Core。
18. 类型名、任务名和目录名必须表达四层归属、读写方向和状态职责。
19. Unity Entities 1.4.6 的 SystemGroup / ISystem / Job / ECB / Enableable / DynamicBuffer / Blob / Baker / Query filter 是 Runtime Core 目标态的第一性技术约束。
20. request entity 不是高频 instant GE 的默认承载；高频路径优先 command data / buffer / stream。
21. hot path 中直接执行结构变化是 P0 违规；结构变化只能在明确 structural playback phase 中发生。
22. DynamicBuffer 不是无限全局消息总线；每类 buffer 必须有容量、生命周期、清空策略和 pressure counters。
23. EntityQuery change filter 是 chunk 级优化，不是精确 gameplay event 语义。
24. Runtime Core 新增系统必须先回答所属 SystemGroup、读写集合、结构变化权限、buffer 生命周期、query filter、Debugger counters。
25. 业务代码评审必须引用 `UnityDOTS官方文档参考/主题/90-规则编号索引.md` 的具体规则编号，不能只引用抽象原则。
26. Runtime Core API 选型必须引用 `UnityDOTS官方文档参考/主题/20-GASRuntimeCore-API选型基线.md`；未评估 `NativeStream`、Chunk Component、Cleanup Component、EntityQuery bulk、system-associated entity、WeakObjectReference / UnityObjectRef 等候选 API 时，不得把当前实现承载视为目标态。
27. Runtime Core 每帧必须能解释 query/filter/allocator/dependency 的成本来源；这些成本不是 Debugger 后补指标，而是目标态 phase contract 的一部分。
28. DynamicBuffer 溢出、chunk fragmentation、shared component unique value、enableable wait、job scheduling overhead 都属于架构健康问题，不得被归类为普通优化项。
29. ExecutionCalculation 目标态不使用托管 delegate 或可变静态注册表；动态计算必须能被 Burst job、generated static switch 或经证明的粗粒度 FunctionPointer 承载。
30. 无头验收不删除表现链路；Cue / UI / VFX / SFX 仍从 Boundary outbox 派生，只是最终 side effect 可替换为结构化日志。
31. AutoChess deterministic 验收必须明确 world time / tick source；不得用 Editor frame delta 或首帧 Burst 编译数据判断 Runtime Core 性能。
32. 目标 Archetype 数量 < 10；不使用 tag component（纯标记无数据字段）—— 所有 tag 状态通过 bitmask 或 enableable 表达。
33. 每个 DynamicBuffer 必须有 `InternalBufferCapacity` 声明和 spill 监控；buffer 外部化是性能退化信号，不是"能用就行"。
34. 每种 Component 必须明确分类为 Data/Buffer/Enableable/Chunk/Cleanup 之一；禁止"ECS component"笼统称呼掩盖选型决策。
35. Frame Arena（query/lookup/allocator/dependency budget）是 Runtime Core 的前置基础设施，不是可选优化；hot path 禁止临时创建 query 或 lookup。
36. Enableable toggle 只在 `GasActiveEffectLifecycleSystemGroup` 执行；其他 phase 对 enableable 只有只读访问；同步 enableable-filtered query 不得在 hot path 无评估使用。
37. Chunk Component 是性能优化，不替代 per-entity 状态正确性；使用 Chunk Component 的 phase 必须有 Debugger 一致性验证。
38. 禁止使用已废弃的 DOTS API（如 `IAspect`，deprecated since Entities 1.4.6）。所有 API 选型必须以当前 PackageCache 版本的非 deprecated API 为准；统一替代方案为直接 component 访问和 query 方法。已有 `IAspect` 使用需在重构窗口替换，新代码不得引入。参见 `P1-09`、`CASE-13`。
39. 工作线程结构变化必须使用 `ExclusiveEntityTransaction`，禁止从 Job 内部直接调用 `EntityManager`（`PRF-21`）。`ExclusiveEntityTransaction` 在安全系统中与 ECB 等价，但允许在工作线程直接执行结构变化；仅在 `Entities.ForEach` 闭包或需要即时结构变化反馈的场景使用，hot path 批量操作仍优先 ECB playback。
40. EntityQuery 创建必须通过 `SystemState.GetEntityQuery`，禁止使用 `EntityManager.CreateEntityQuery`（`PRF-33`）。通过 SystemState 创建的 query 能被安全系统追踪、参与 dependency 管理；直接 `EntityManager` query 无法被系统自动管理生命周期和依赖完成。
