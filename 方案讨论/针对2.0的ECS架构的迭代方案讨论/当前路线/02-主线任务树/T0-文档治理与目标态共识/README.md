## 主线目标

1. 入口文档只做索引和维护规则。
2. 当前事实、目标态 Spec、任务树、进度状态分别归属清晰。
3. 各节点（分支节点和叶子节点）都能作为 Agent prompt 的上下文。
4. 官方 DOTS 文档结论能通过覆盖矩阵、`ODF-*` 规则、行动报告、迭代摘要和任务树形成闭环。

## 非目标

1. 不记录 Runtime 实现流水。
2. 不把历史方案直接晋升为当前事实。
3. 不在文档治理主线内替其他主线决定实现细节。

## 执行范围

1. `当前路线/README.md`
2. `当前路线/00-*` 到 `当前路线/04-*` 子目录
3. `当前路线/历史方案参考/`
4. `迭代记录/README.md` 和入口级迁移说明

## 执行细则

1. 新增长期结论必须进入 `00` 或 `01`，不能只留在迭代记录。
2. 新增任务必须进入 `02` 对应主线 / 支线节点。
3. 旧方案只通过 `01-目标态架构共识/` 对应 Spec 的 `历史方案定位` 折算。
4. 官方文档新结论先进入 `UnityDOTS官方文档参考` 对应主题，再反哺到目标态业务 Spec、任务树、当前事实和治理规范。

## 验收门槛

1. `当前路线/README.md` 是根部唯一入口，根部不再维护旧 `00-06.md` 入口文件。
2. `02` 任务树的主线、支线、任务节点均满足 Prompt 字段。
3. 旧 owner 引用不会误导后续执行。
