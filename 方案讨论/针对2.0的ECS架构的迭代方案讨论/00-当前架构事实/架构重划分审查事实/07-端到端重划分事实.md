## 本轮端到端事实结论

当前 EX-GAS 已经具备一条可演进的 ECS Runtime 主链，但端到端职责仍没有完全按 Shell / Boundary / Core / Debugger / Definition 分离。最关键的事实不是“是否存在 ISystem”，而是调用方仍在多个位置必须理解 ECS handle、singleton owner、generated lifecycle、NativeContainer owner、capacity 或 observation cost。

| 端到端切片 | 当前代码事实 | DOTS 判定 |
|---|---|---|
| Runtime install / tick | `GASManager.Initialize()` 集中创建 World、system group、全局 singleton 和 Debugger；AutoChess host / ticker 通过 Shell 获取 World、group 和 job drain | bootstrap owner 已集中，是正向事实；但 RuntimeSession seam 仍未把 World / EntityManager / job drain 从业务 adapter public 语义中彻底隔离 |
| Shell command write | `GASRuntimeShell.TryCreateASCCommandPort(...)` 与 `AbilitySystemBinding.Commands` 已把外部 command 集中到 command port | 写入口方向正确；但同一 Shell facade 仍能创建 read model、解析 singleton、drain jobs 和 bind presentation，capability 未分级 |
| Core command resolve | `ASCCommandBufferResolveSystem` 已使用 `ISystem`、stored query、type handle、enabled mask、scheduled `IJobChunk`、ECB 和 catalog | DOTS API 形态正向；但单个 job interface 过宽，command、ability slot、tag mask、attribute base value 和 fact 写入仍在同一 lane |
| Effect fan-in / frame stream | `GEEffectCommandSpecStream` 删除了 fallback query，但 command / set-by-caller / spec / delta / mutation / fact 仍共用 singleton carrier；`MergeParallelCommandFanIn` 仍用 managed `List` 排序后写回 singleton buffer | `BUF-02` / `NAT-03` 判定为迁移 proof；删除 fallback query 或局部 NativeStream 切片不能证明 scale-ready fan-in |
| Active effect lifecycle | generated `GASActiveEffectMutationApplySystem` / `GASActiveEffectPreTickSystem` 已有 gather、owner range、snapshot map、chunk apply；slot SourceAttribute snapshot key 和 capacity estimator 已存在 | active effect store 方向正向；但 lifecycle owner 仍在 generated artifact 中，且 capacity / spill / lane-specific evidence / x100-x1000 未闭合 |
| Definition consumption | generated catalog lookup、activation plan、GE seed、modifier record、magnitude evaluator、TagRequirement evaluator 已是 unmanaged / Blob-oriented pure resolver；Ability/GE all-any-none requirement 当前进入 `GASDefinitionCatalogBlob.Requirements` | 这是 Definition & Generation 的正向保留面；不应与 generated lifecycle system 混为同一完成度 |
| Debugger / evidence | Debugger 记录 RuntimeCore、frame backbone、magnitude source、observation materialization 等 counter；structured export / official diff / validation evidence 已出现 | Debugger 已是 evidence owner；derived export、observation materialization 和 official capture 必须独立计时，不能混入 CoreSimulation 结论 |
| AutoChess adapter | AutoChess Integration/GasCore 已拆出 host、catalog session、observation gateway、lifecycle、ticker、report projector；但仍通过 Shell 解析 World / EntityManager / singleton / job drain | Demo adapter 是 Application Shell 验收层；当前是 proof-compatible adapter，不是 Thin Adapter 完成态 |

## 续轮接口深度与 owner locality 审查

本轮继续按 Module / Interface / Implementation / Depth / Locality / deletion test 复核端到端链路。当前事实是：目录、namespace、facade 名称和 generated 文件分类都不能单独证明 owner 已归位；只有调用方不再需要理解 query、lookup、allocator、dependency、carrier、capacity、merge、structural playback 和 diagnostics owner，才说明接口变深。

| 审查对象 | 当前 codedb 事实 | 当前事实判定 |
|---|---|---|
| Runtime module graph | `Assets/GAS/Runtime` 主社群为 141 files / 1968 indexed symbols，中心文件仍同时覆盖 Core、Definition、Debugger、Shell、schedule contract、query layout、runtime archetype 和 command resolve | Runtime folder 已形成 DOTS backbone，但还不是按 owner 拆开的深 Module；dependency graph 仍显示多主题聚合 |
| `GASRuntimeShell` | outline 为 281 行，直接消费者仍是 AutoChess lifecycle / observation / runtime host、Editor `GASWatcher` 和 `AbilitySystemBinding` 5 类 | 当前是多 capability ECS handle facade；deletion test 会把 World / EntityManager / singleton / job drain / snapshot / command 复杂度外溢到多个调用方 |
| `ASCCommandBufferResolveSystem` | outline 为 924 行，单个 job 处理 ASC command、Ability grant / activate / remove、Tag diff、Attribute base value、Ability lifecycle request 和 GameplayEvent fact | DOTS API 形态正向，但 lane interface 仍过宽；职责应继续按 command resolve、ability slot、tag diff、attribute command、fact projection 归因 |
| `GEEffectCommandSpecStream` | outline 为 1118 行，拥有 singleton owner、command/spec/delta/mutation/fact buffers、managed list fan-in merge、frame-local pressure counter 和 capacity helper | 删除 fallback query 是正向事实；但它仍是迁移期 carrier，不是 scale-ready fan-in store |
| `RuntimeActiveEffect.gen.cs` | outline 为 3576 行，包含 3 个 generated lifecycle systems、snapshot gather、mutation gather / apply、active effect tick、cleanup、magnitude counters 和 structural ECB owner | active effect snapshot / mutation 方向正向，但 generated lifecycle owner 仍未退出；不能写成 SourceGenerator 目标态完成 |
| `GasRuntimeDebugger` | outline 为 4092 行，包含 diagnostics counters、observation materialization、magnitude source counters、runtime core counters、official diff / export | Debugger 是 evidence owner；observation / derived export / official capture 不得混入 CoreSimulation 性能证明 |

本轮 DOTS 对照口径保持：`QRY-01` / `JOB-01` 支持 hot path 采用 stored query + chunk job；`NAT-03` 要求 `NativeStream` 有 deterministic merge、allocator owner、segment / memory budget 与 dispose 证据；`DBG-01..05` 要求 Contract / Plan、Runtime Counter、Official Capture、Validation Evidence、Derived Export 分层；`BLOB-01` / `BLOB-02` 要求 Runtime hot path 只消费 Blob / generated lookup / pure glue；`ODF-04` 要求目标态变化进入 `01`，当前问题进入 `00`，执行任务进入 `02`。

## 保留面与退出面

| 类型 | 当前应保留 | 当前必须退出或隔离 |
|---|---|---|
| Shell / Boundary | `ASCCommandPort`、`ASCReadModel` 的集中入口方向；AutoChess 多 owner adapter 拆分方向 | `GASRuntimeShell` 作为 world/entity manager/singleton/job drain/read/write/presentation 共享 facade |
| Core | 5 段 physical group、stored query、IJobChunk、enableable mask、ECB phase、owner chunk applicator | 单个 command resolve job 继续承载过多 gameplay 语义；generated lifecycle 继续拥有 query / ECB / NativeContainer |
| Fan-in | execution output typed fact 的 `NativeStream` deterministic merge 切片；stream pressure evidence | singleton DynamicBuffer 作为默认 command/spec/delta/fact/mutation 总线；managed list merge helper 作为 hot path 终局 |
| ActiveEffect | owner-local slot / global index / slot SourceAttribute snapshot key 是正向 store 证据 | generated active effect lifecycle owner、缺 lane-specific attribution、缺 capacity pressure / spill、缺非零业务样本 |
| Definition | `GASDefinitionCatalogBlob`、generated lookup、pure resolver、validation graph | SourceGenerator 生成 Runtime Core lifecycle、system registration、hidden query、hidden ECB 或 NativeContainer owner |
| Debugger | structured counter、official diff、validation evidence、observation materialization counter | 字符串日志、Mermaid 图、中文 summary、disabled profiler reason 或 `blockingDebugErrors=0` 作为性能完成证明 |

## 不能推出的结论

1. 不能因为 Runtime `SystemAPI.Query=0`、`CreateEntityQuery=0` 就写成 DOTS 性能优秀；Debugger / Cue `ToEntityArray` 和 runner sync 仍需要独立计时、频率和污染隔离。
2. 不能因为 generated runtime type 缺失已 fail-fast 就写成 SourceGenerator 职责边界完成；generated artifact 仍有 `ISystem`、`OnUpdate`、lookup、ECB 和 NativeContainer owner。
3. 不能因为 active effect slot SourceAttribute snapshot key / gather job 存在，或 TagRequirement all-any-none 已进入 generated catalog，就写成 active effect lifecycle store-only、magnitude snapshot lane release-ready 或业务 tag 组合全覆盖；还缺容量压力、spill、非零业务配置和规模 profile。
4. 不能因为 AutoChess x50 或 validation report 通过，就写成 AutoChessDemo 测试链完善；Goal 停止条件仍缺 x100 / x1000、Unity Test Runner、Profiler / Journaling enabled 和 SourceGenerator / Luban 重跑。
5. 不能把 `GASRuntimeShell` 注释中的 Thin Shell 语义当成当前事实；当前事实以 direct consumers、暴露 capability 和内部 ECS handle 解析为准。

## 对任务领取的事实约束

1. R1/R6 领取前必须复核 `GASRuntimeShell` direct consumers、AutoChess host / observation / lifecycle / ticker 对 World、`EntityManager`、runtime singleton 和 job drain 的依赖。
2. R2/R3 领取前必须复核 `GASRuntimeStreamOwnerPlanner.CreateCurrent()` 的 current carrier / target carrier / scale status，以及 `GEEffectCommandSpecStream` 的 singleton buffer 写入点。
3. R4/R8 领取前必须复核 Debugger / Cue `ToEntityArray` owner 分类、observation materialization counter、performance / diagnostic pass 分离和 official capture state。
4. R5 领取前必须复核 generated runtime artifact 的 `ISystem` / `OnUpdate` / lookup / ECB / NativeContainer 命中，并把 pure glue 与 lifecycle owner 分开验收。
5. R7 领取前必须复核 active effect lifecycle owner 是否仍在 generated artifact / static helper 中，以及 active effect slot snapshot lane 是否具备 capacity / spill / lane evidence。
