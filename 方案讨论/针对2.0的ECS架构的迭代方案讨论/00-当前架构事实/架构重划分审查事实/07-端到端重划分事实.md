# 07 端到端重划分事实

> Owner：`00-当前架构事实/架构重划分审查事实` | 最近复核：2026-08-24 | 状态：当前事实

本页只记录当前 Shell -> Boundary -> Core -> Structural -> Observation 链。v1 目标态由 `../../01-目标态架构共识/17-GAS业务链路破坏性重划分Spec.md` 维护，执行入口由 `../../02-主线任务树/RuntimeV1不可兼容迁移/README.md` 维护。

## 当前端到端结论

当前代码已有 owner-local command/spec/fact、Blob Catalog、scheduled job 和结构化 evidence 等正向资产，但 gameplay authority 与运行 owner 仍分散在 Ability Entity、ASC-local slot、legacy GE entity、singleton stream、EventBus 和多个 Boundary consumer 中。

| 切片 | 当前代码事实 | 当前判定 |
|---|---|---|
| Session/bootstrap | `GASManager` 创建独立 World、五段 GAS group、Timer、stream、global index、EventBus、Replay 与 Debugger | 安装 owner 已集中；Shell/runner 仍能理解 World、EntityManager、group 和 job drain |
| Boundary command | `ASCCommandPort`/AutoChess 写 ASC owner-local command | 入口方向正向；port/handle 内部仍包裹 raw Entity/EntityManager |
| Ability | grant 产生 Ability Entity，ASC slot 保存 Entity，多个 System 处理 activate/commit/lifecycle/cleanup | 不是 ASC-local 单一 slab authority |
| Effect | instant/active 新链走 owner-local data，legacy generic execution 仍查 GE entity | owner-local slot 与 legacy GE entity 双权威并存 |
| Definition | generated Blob/lookup/pure magnitude evaluator已进入 Runtime | 可保留基础；Requirement phase 当前被压平 |
| Fact | producer 写 `OwnerLocalGameplayFactBuffer`，Boundary 的 `GameplayBoundaryFactExportSystem` 排序导出 | 旧 `GameplayOwnerLocalFactFlushSystem` 已不存在；当前仍非单 Drain |
| Presentation/Replay/Diagnostics | 多个 Boundary System 直接读 observation 或派生 buffer | 多 consumer ECS 读取与 cursor/projection state 尚未收口 |
| Cue | only-OnApply fact、Null CueEntity、bridge/lifecycle 未注册 | 当前 managed Cue 链断开 |
| AutoChess | runner 手工更新五个自定义 group，并插入自定义 command/damage System | 与标准 EndFixed、单 kernel不兼容，必须同步迁移 |

## 当前消息流

```text
Application / AutoChess
  -> GASRuntimeShell / ASCCommandPort
  -> ASC owner-local command
  -> 五段 GAS physical schedule
  -> Ability Entity + owner-local GE + legacy GE execution
  -> OwnerLocalGameplayFactBuffer
  -> GameplayBoundaryFactExportSystem
  -> BoundaryObservationFactBuffer
  -> Presentation / Replay / Diagnostics 各自消费
```

这条链已能运行，但不是单向深 Module：Shell 仍有多 capability，Core 有多 authority，Boundary 有多 consumer。

## 当前时序风险

1. CommandResolve 中的 Ability commit 与后续 GE/Attribute 可以同 tick完成。
2. Attribute threshold lifecycle 当前同 tick进入 cancel/end/cleanup。
3. period/overflow 当前显式写 next-frame buffer。
4. Ability grant 通过 ECB 创建 Entity，最早下一 tick进入 Ability 查询。
5. `ASCDestroyFinalizeSystem` 在 Boundary 写自定义 ECB，已错过当前 StructuralCommit，physical destroy 通常延迟到下一 tick。
6. 若未来把 ASC destroy 提前到标准 EndFixed，而 terminal fact 仍只存在 ASC-local outbox，post-Fixed Drain 前会有事实丢失风险；这是迁移约束，不是当前已修复事实。

## 当前依赖与删除影响

- Ability Entity 相关类型影响 ASC resolve、Ability try/commit/tick/lifecycle/cleanup、ActiveEffect granted ability、Destroy finalize、Debugger 与 Editor watcher，不能局部替换。
- legacy GE 相关类型影响 ASC archetype/factory、GE factory/config registry、execution、magnitude、cleanup、Debugger 与 Destroy finalize。
- `AutoChessGasRuntimeTicker`、`AutoChessRuntimeSystemBootstrap`、validation timing/report 直接依赖旧五组和旧 system 名。

因此 Runtime v1 必须以不可兼容集成窗口切换，不能保留按 Definition/feature flag 选择旧/新 backend 的双路。

## 当前可提取资产

以下只是当前可提取事实，不是本页设计目标态：

- immutable Catalog、generated lookup、pure evaluator；
- owner-local command/spec/fact 的数据方向；
- deterministic sequence/comparer；
- Base/Current Attribute 与 tag mask/query 基元；
- structured diagnostics/evidence；
- AutoChess 业务 workload 和历史 hash 样本。

## 不能推出的结论

1. 使用 `ISystem`/Job 不等于单 writer 或正确 GAS 语义。
2. owner-local data 已出现不等于稳定 slab、唯一 authority 或 scale-ready。
3. 当前五段 group 是现实调度，不是 v1 保留门。
4. 历史 x50 report 不等于真实 Unity tests、Profiler、x100/x1000 已完成。
5. Cue managed 类型存在不等于实际注册或播放成功。
