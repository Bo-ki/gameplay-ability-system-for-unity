# P1 高风险缺陷

> 最近审查：2026-06-06 | 事实源：当前代码

P1 记录不会立即阻断主链，但会持续扩大维护成本、性能风险或目标态偏差的问题。

## P1 分类边界

本页不再把所有直接 `EntityManager`、managed registry、主线程查询都一律升为 P0。当前分类口径如下：

| 分类 | 判定标准 | 当前处理 |
|---|---|---|
| P0 | 发生在 Runtime Core hot path，且会破坏 frame phase、结构变化边界或高规模确定性 | 必须进入主链修复任务 |
| P1 | 集中在初始化、Boundary、Demo adapter、generated 过渡系统或 managed presentation，但会扩大维护/性能风险 | 需要 owner 化、迁移计划和证据跟踪 |
| P2 | 主要是命名、文档新鲜度、检查流程或任务治理问题 | 作为后续治理建议 |

因此 `AutoChessGasCoreBridge` 这类集中 adapter 内的直接 `EntityManager` 操作属于 P1/P0 交界：初始化、catalog 安装、observation reset 可暂按 P1 管理；如果同类写法进入 `GASCoreSimulationSystemGroup` 热路径，就必须升为 P0。

## P1-A：5 段物理主链与 8 个逻辑 phase contract 并存

1. `GASFramePrepareSystemGroup`
2. `GASCommandResolveSystemGroup`
3. `GASCoreSimulationSystemGroup`
4. `GASStructuralCommitSystemGroup`
5. `GASBoundaryProjectionSystemGroup`

`GASSystemScheduleContract` 内还保留 8 个逻辑 phase 枚举：

- FramePrepare
- CommandIngest
- SpecEvaluation
- ActiveEffectLifecycle

这不是错误，但文档和任务必须区分“物理 group”与“逻辑 phase”。当前代码不是旧 8 个 physical group，也不是旧 `GasStructuralPlaybackSystemGroup`。

## P1-C：typed fact 与 Boundary 派生缓冲并存

当前 positive fact：

1. `GameplayFactProjectionSystem` 已能把 delta 投影为 `GameplayEventBuffer` typed facts。
2. `GameplayFactProjectionSystem` 已改为 scheduled `IJob`，只写入 `GameplayEventBuffer` typed fact，不再持有 EventBus lookup，也不再写 Attribute/Cue 边界缓冲。
3. `GameplayFactBoundaryProjectionSystem` 位于 BoundaryProjection，负责从 typed fact 派生 Attribute/Cue/Tag 边界缓冲。
4. `PresentationOutboxProjectionSystem` 与 `ReplayLogSystem` 位于 BoundaryProjection，且只消费 `GameplayEventBuffer` typed fact。
5. `AutoChessExecuteDamageCalculationSystem` 已只写 typed fact，不再兼容旧 gameplay event bus。
6. `DamageEventBuffer`、`EventBusHelper.EnqueueDamageEvent`、`EventBusHelper.EnqueueAttributeChangeEvent`、`EventBusHelper.EnqueueCueRequest`、`EventBusHelper.EnqueueTagChangeEvent` 已退场。

- `GameplayEventBusComponent` 仍作为 Attribute/Cue/Tag 边界缓冲和 presentation outbox owner 的 singleton owner 存在。
- Attribute/Cue/Tag 边界缓冲必须保持 BoundaryProjection 派生语义，不能重新成为 Core/helper/generated 的事实写入口。
- 如果业务 reaction 继续从 EventBus 扫描，就会把 Observation 重新拉回 CoreSimulation。

## P1-D：Cue 仍是 managed presentation bridge

当前 `CueManagedInstanceComponent` / `GameplayCueBase` 等 managed cue 路径位于 BoundaryProjection。作为表现桥接可接受，但它不能被当作 Burst gameplay core。

1. Cue 不应反馈 CoreSimulation。

## P1 退出条件

1. 文档统一使用当前 5 段 physical group 名称，并明确 8 phase 只是逻辑 contract。
2. 未注册系统有去留结论：启用、删除或归档。
3. typed fact 与 legacy EventBus 的职责分界清晰，业务 reaction 不再依赖 observation bus。
4. managed registry/helper/cue 路径全部标注为初始化、authoring 或 presentation，不混入 CoreSimulation。
5. AutoChess bridge 的结构变化被纳入明确 owner 或 request/command 模式。
6. generated active mutation 的 singleton serial job / BufferLookup / ComponentLookup store 有去留结论或拆分计划；已收口的 ability lifecycle、attribute owner marker 和 execution output applied 链路继续由 static validation 防回流；已 job 化链路需要补 dependency/order/capacity 证据，并用 static validation 防止 `.gen.cs` 回到未 Burst、random enableable 或主线程 proof 形态。

## 下一轮瘦身优先级

本轮已删除旧事实源，不做兼容适配。后续优先级调整为：

1. **模板级治理 generated active mutation**：active mutation 仍是 P1 中最重的 generated 风险。修复必须改 `GasGlueCodeGenPhases` 和 validation report，再生成 `.gen.cs`，不允许手改生成产物。
2. **分层 `GASManager.EntityManager`**：global facade 使用面要按 bootstrap、Boundary、Debugger、demo adapter、prototype 和 Runtime Core 分类。当前已删除部分 Runtime helper 无参全局入口，并用 static gate 禁止 generated/template 回流；handwritten Runtime Core/helper 的全局写入口要继续清零或白名单化。
3. **Boundary 缓冲防回流**：Attribute/Cue/Tag 边界缓冲只允许由 `GameplayFactBoundaryProjectionSystem` 派生，static gate 继续禁止 helper/generated/template 直接写这些缓冲。
4. **结构变化证据闭环**：StructuralCommit gate 已存在，下一步必须用 Journaling/Profiler/Debugger counters 证明 create/destroy/add/remove/enable/disable 来源和 phase。
