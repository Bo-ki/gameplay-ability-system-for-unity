# P0 致命缺陷

> 最近审查：2026-06-08 | 事实源：当前 Runtime / Generated Runtime / AutoChessDemo 代码

P0 只记录会直接破坏 Runtime 边界、结构变化治理、hot path 可扩展性或证据可信度的问题。旧文档中的 `S*` 文件名、旧 group 名称和“22 个 ToEntityArray 热路径”不再作为当前 P0 事实。

## P0-A：Runtime Boundary request entity 链路已退场，需防回流

`ASCCommandPort` 不再通过 `GASManager.EntityManager.CreateEntity()` 创建 request entity。当前边界入口改为写 ASC owner-local buffer，并用 enableable pending marker 触发 resolver：

| 路径 | 代码事实 |
|---|---|
| `RequestDestroy()` | 追加 `ASCDestroyCommandBuffer`，启用 `ASCCommandPendingComponent` |
| `RequestInitialize()` / `RequestSetLevel()` / tag / attr | 追加 `ASCCommandBuffer`，由 `ASCCommandBufferResolveSystem` 消费 |
| ability grant / activate / end / cancel / remove | 追加 `AbilityCommandBuffer`，由 `ASCCommandBufferResolveSystem` 消费 |
| `RemoveGameplayEffects()` / `ClearGameplayEffects()` | 追加 `GERemoveCommandBuffer`，启用 `GERemoveCommandPendingComponent` |

已删除的旧链路包括：`ASCEntityCreateSystem`、`ASCInitializeRequestSystem`、`ASCCommandRequestSystem`、`AbilityCommandRequestSystem`、`ASCDestroyRequestSystem` 以及对应 `*RequestComponent`。`GameplayEffectLegacyBridge.TryCreateLegacyRequestEntity()` 兼容桩也已删除。

**当前要求**：新增/迁移 API 只能进入 owner-local command buffer、明确 stream 或 structural ECB，不得重新扩张 facade 同步 request entity 路径。Debugger / structural plan / 文档命名也不得继续把 pending owner 叫作 request entity。

## P0-B：核心同步等待已清零，仍需防回流

`state.Dependency.Complete()` 当前在 `Assets/GAS/**/*.cs` 中命中 0 处。第二轮深修已把上一版记录的 6 个同步等待全部移除：

| 文件/链路 | 当前状态 |
|---|---|
| `ASCDestroyFinalizeSystem` | 并行 scan jobs + scheduled apply job；不再主线程 `Complete()` 后消费 |
| `AttributeThresholdAbilityLifecycleRequestSystem` | scheduled `IJobChunk` 直接写 enableable lifecycle request，并用 ECB 延迟追加 fact |
| `GEExecutionCalculationSystem` | scheduled `IJobChunk` 计算 output buffer 与 execution fact |
| `GEExecutionCalculationOutputModifierSystem` | 删除小规模主线程 fallback；`NativeStream` fan-in 后 scheduled merge job 排序、写属性、追加 delta |
| generated `GASActiveEffectPreTickSystem` | 删除 `SystemAPI.Query` pre-scan 与 `NativeStream -> Complete -> ApplyActiveEffectTickRecord`；改为 scheduled `GEActiveEffectPreTickJob` |
| `GasGlueCodeGenPhases` active-effect 模板 | 与 generated output 同步，防止重新生成旧 `Complete()` 链路 |

本条仍保留 P0 监控等级：`Complete()` 清零只是最低门槛，后续新增系统或 codegen 模板若重新出现 `Complete()`、`.Run()`、Temp ECB playback，必须视为阻断项。

## P0-C：generated runtime 已进入主链，P0 只保留 active mutation 与防回流

`GASSystemScheduleContract` 当前通过手写 generated type-name 列表把 7 个 generated systems 注册到当前主链；`RuntimeSystemRegistration.gen.cs` 已退场：

- `AbilityCatalogCommitSystem`
- `GEEffectCommandCatalogNormalizeSystem`
- `GEEffectSpecBuildSystem`
- `GASActiveEffectMutationApplySystem`
- `GASAttributeSetReduceApplySystem`
- `GASActiveEffectPreTickSystem`
- `GASActiveEffectRemoveSystem`

这些系统不是纸面 Contract，已经修改 runtime state。第二轮代码修复后，下列旧诊断已退场：

1. `AbilityCatalogCommitSystem` 不再用 `ComponentLookup<AbilityCommitRequestComponent>.SetComponentEnabled` 随机关闭当前 commit request；当前通过 `ComponentTypeHandle<AbilityCommitRequestComponent>` 取得 chunk-local `EnabledMask`，在 `IJobChunk` 内按 index 关闭 request，并通过 `EndRequestTypeHandle` + chunk `EnabledMask` 写 auto-end request，符合 `EN-03`、`CASE-20` 和 `PRF-22`。
2. `GEEffectSpecBuildSystem` 与 `GASAttributeSetReduceApplySystem` 已由 codegen 模板输出 scheduled `[BurstCompile] IJob`，符合 `BUR-01` 的最低热路径要求。
3. instant GE spec build 已支持 cue-only 配置：`CanBuildInstantSpec` 允许 `ModifierCount > 0 || GameplayCueCode > 0`。
4. `ASCDestroyingComponent` 的销毁判定已改为读取 enableable bit；默认 disabled 的正常 ASC 不再被 `HasComponent` 误判为 destroying。
5. `GASActiveEffectMutationApplySystem` 已调度 `GASGeneratedActiveEffectRuntime.GEActiveEffectMutationOwnerCommandCollectJob : IJobChunk` + `GEActiveEffectMutationOwnerCommandFinalizeJob : IJob` + `GEActiveEffectMutationChunkApplyJob : IJobChunk`；旧 public/static `TryApplyActiveMutation(EntityManager, ...)` helper、旧 `GEActiveEffectMutationGatherJob : IJob` singleton command scan 和旧 `GEActiveEffectMutationApplyJob : IJob` serial apply 已退场。
6. `AbilityCatalogCommitSystem` 已移除 `NativeList<GECommandSeedRecord>(Allocator.TempJob)` per-frame seed scratch，模板改为直接构造单条 seed 并 append command。
7. `GasCodeGenValidationReport.md` 已加入 generated runtime hot path gate；当前 `GeneratedHotPathRegressionHits: 0`，可阻断 `Complete()`、`.Run()`、legacy EventBus writer、旧 public/static active mutation helper、ability seed scratch、hot path `Allocator.Temp`、旧 remove pending lookup、`HasComponent<ASCDestroyingComponent>`、旧 ability lifecycle lookup、旧 `AttributeDirtyLookup` / `ActiveModifierPresentLookup` 回流。
8. generated active effect 的 ASC dirty / active modifier present 已改为写 `AttributeOwnerMarkerRequestBuffer`，再由 `AttributeOwnerMarkerRequestSystem` 以 ASC-owned chunk `EnabledMask` 应用；`GEExecutionCalculationOutputModifierSystem` 的 effect applied marker 也改为 effect-owned chunk applicator。
8. `ASCCommandBufferResolveSystem` 已用两段 job 先标记 destroying、再解析命令；ASC owner-local pending/destroying/dirty 均用 chunk `EnabledMask` 写入，避免同帧 target 可用性取决于 chunk 顺序。

当前 P0 仍成立的 generated 风险已从 active mutation random lookup 转为防回流与语义闭环：

1. `GASActiveEffectMutationApplySystem` 的 command source 已由 `GEEffectCommandCatalogNormalizeSystem` 投影到 ASC owner-local `ActiveEffectMutationCommandBuffer`，active mutation 的 set-by-caller payload 也已复制到 ASC owner-local `ActiveEffectMutationSetByCallerValueBuffer` 并在 collect 阶段展平成 frame-local list；apply 阶段仍是 ASC chunk-local `IJobChunk`，`activeMutationEstimatedRandomLookups=0` / `activeMutationOwnerResourceLookups=0` / `activeMutationMigrationCarriers=0` 已有 x50 runner 证据。当前仍不能宣称全链路 scale-ready：request / ability / period / overflow instant producer 已退出首跳 singleton，但非 active mutation 的 `GESetByCallerValueBuffer`、instant spec build 与 spec carrier 仍在 singleton command/spec stream 上。
2. active mutation chunk apply 不再持有 `BufferLookup<AttributeValueBuffer>` 与 writable `BufferTypeHandle<AttributeValueBuffer>` alias；为避免 Unity safety alias，跨 owner `SourceAttribute` 读取已退出 active mutation apply。后续必须用 magnitude snapshot / resolve lane 恢复完整 SourceAttribute 语义，而不是把 fallback magnitude 当业务终局。
3. generated code 的 job 化必须同步到模板，不能只改生成结果；当前 static gate 已覆盖 ability lifecycle lookup、ASC dirty/present lookup、execution output applied lookup、旧 active mutation singleton gather、旧 active mutation serial job 和旧 active mutation random lookup 估算等已退场 hot path 模式。后续仍要阻断 generated active mutation 重新引入主线程 helper、Temp ECB playback、无 Burst hot job 或 unchecked singleton command/set-by-caller carrier 扩张。

生成代码身份仍不能豁免 DOTS 规则；凡是 generated system 写 attribute、active effect、fact 或结构变化，都必须有 query/job/dependency/ordering 证据。

## P0-D：singleton stream owner 被当作多条 hot path 的事实源

`GEEffectCommandStreamComponent` owner 当前承载至少以下 buffer：

- `GEEffectCommandBuffer`
- `GESetByCallerValueBuffer`
- `GEEffectSpecBuffer`
- `GameplayEventBuffer`

这使 command/spec/fact 迁移链能跑通，但它是 proof-only carrier，不是 scale-ready 架构。2026-06-07 本轮已删除 `GEEffectCommandSpecStream` 的隐式 singleton writer/append helper，Runtime helper 需要显式解析 stream owner 后写入；这只是 API 承载收窄，不改变多数 producer/consumer 仍汇聚到单 entity DynamicBuffer 的事实。

## P0-E：结构变化集中化缺少证据闭环

当前 `GASStructuralCommitSystemGroup` 和 `Begin/EndGASStructuralCommitECBSystem` 已经是真实物理 gate。正向事实成立，但还不能宣称结构变化已经全部收口：

1. Boundary facade 的 request entity 链路已退场，但 ASC 创建仍是 facade 同步创建 ASC runtime owner，需要明确低频外部入口语义。
2. Config/prototype/demo bridge 仍有直接 `EntityManager.CreateEntity()` / `DestroyEntity()`；其中 config component 自身的隐式全局 `GASManager.EntityManager` facade 已删除，prototype factory 改为显式传入 world `EntityManager`。
3. `ASCCommandBufferResolveSystem` 与 generated active effect 通过 `EndGASStructuralCommitECBSystem.Singleton` 记录结构变化；pre-tick 已 scheduled job 化，但仍需要 Journaling 证明 playback 相位、数量和来源。
4. `GasRuntimeOfficialToolDiff` 已能用 `EntitiesJournaling` 抓结构变化记录，但文档不能把工具存在当完成证明。

本条需要区分三类直接 `EntityManager`：初始化/authoring/prototype 路径可以暂时保留，Boundary facade 需要优先治理，CoreSimulation hot path 直接结构变化必须视为不合格。当前 P0 只针对后两类，不把所有初始化写 ECS 一刀切为 hot path 违规。

## P0-F：Observation 成本与 CoreSimulation 成本仍需隔离

旧“22 个 ToEntityArray 热路径”已经不成立；当前 `ToEntityArray` 主要在：

- `GasRuntimeDebugger` observation 路径两处
- `CueManagedLifecycleSystem` Boundary managed presentation 路径
- `GasRuntimeDebugger` singleton lookup 已改为 registered/cache owner，并由诊断脚本阻断 `CreateEntityQuery` fallback 回流
- `GASRuntimeFrameContext` current-frame registered/cache owner 已删除 singleton fallback，仍需保持防回流验证
- `ActiveEffectStore` global index owner 已改为 registered/cache owner；剩余风险是 capacity / cache integrity / hot path 证据

新的 P0 不是 `ToEntityArray` 数量，而是证据污染：如果 Debugger、Replay、Presentation、Official diff 的同步 query 成本与 CoreSimulation 混在同一性能结论里，后续架构判断会失真。

## 当前 P0 退出条件

1. request entity 旧链路不回流；owner-local command buffer / pending marker 成为唯一 boundary command 入口。
2. `Complete()` / `.Run()` / Temp ECB playback 保持扫描为 0。
3. singleton stream owner 的每类数据都有明确迁移去向或容量/ordering 证据。
4. `GasRuntimeOfficialToolDiff` / Profiler / Debugger counters 能证明结构变化只在预期 phase 发生。
5. CoreSimulation 性能报告与 Observation/Debugger 成本分离。
6. generated static validation 能阻断 `.gen.cs` 回流到无 `[BurstCompile]` hot job、已退场 current-entity random `ComponentLookup.SetComponentEnabled`、`HasComponent<ASCDestroyingComponent>` 销毁误判、Temp ECB playback 或 `state.Dependency.Complete()`。
