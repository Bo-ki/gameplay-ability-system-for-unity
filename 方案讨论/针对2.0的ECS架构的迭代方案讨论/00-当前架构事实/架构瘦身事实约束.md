## 官方依据

本轮事实判断对照本项目当前 Entities 包文档 `Library/PackageCache/com.unity.entities@e90944159b94/Documentation~` 和 `../../UnityDOTS官方文档参考/主题/90-规则编号索引.md`：

| 规则 | 对当前事实的约束 |
|---|---|
| `QRY-04`、`PRF-06`、`PRF-19` | `ComponentLookup` / `BufferLookup` 可以作为工具，但高频 random write 必须有 owner-local / chunk-local / target-grouped 选型证据。 |
| `SC-01`、`ECB-03`、`PRF-02`、`PRF-04` | 结构变化必须集中到明确 playback phase，并用 Journaling / Profiler / Debugger 证明来源和相位。 |
| `BUF-01`、`BUF-02`、`NAT-03` | singleton DynamicBuffer 只能作为 proof / 低量 carrier；fan-in 必须有容量、merge 顺序和内存预算。 |
| `EN-03`、`CASE-20`、`PRF-22` | 高频 enableable 写入优先 current chunk `EnabledMask` 或 owner applicator；cross-entity marker 写入必须归并。 |
| `ODF-06`、`ODF-18` | 后续任务必须交还 API 选型和官方依据，不允许只用“已 job 化”作为完成证明。 |

## 事实约束

1. generated active mutation 的修复必须落回 `GasGlueCodeGenPhases`、manifest/report gate、sourcegen bat/CLI 和 Unity batchmode 生成链路；不能手改 `.gen.cs`。
2. `GASManager.EntityManager` 只能按 bootstrap、authoring/prototype、Boundary Cue、Debugger、Demo adapter 等白名单分类；Runtime Core hot path 不得通过 global facade 写 ECS。
3. Attribute / Cue / Tag / Damage 边界缓冲只能由 BoundaryProjection 或表现桥派生；CoreSimulation、CommandResolve 和 generated runtime 不得直接写。
4. StructuralCommit gate 必须用 Journaling / Profiler / Debugger counters 证明 create / destroy / add / remove / enable / disable 来源和 phase。
5. 后续任务交还时必须同时给出静态 gate、生成链、编译或运行验证证据；若只完成文档或模板改动，需要明确哪些 runtime proof 仍未跑。
