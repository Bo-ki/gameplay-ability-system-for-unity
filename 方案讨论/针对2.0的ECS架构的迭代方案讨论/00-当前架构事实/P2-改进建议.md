# P2 改进建议

> 最近审查：2026-06-02 | 事实源：当前代码与当前事实文档

P2 记录不阻断当前主链，但能降低后续误判、重复返工和维护成本的事项。

## P2-A：统一命名口径

当前文档必须使用现实代码中的物理 group 名称：

- `GASFramePrepareSystemGroup`
- `GASCommandResolveSystemGroup`
- `GASCoreSimulationSystemGroup`
- `GASStructuralCommitSystemGroup`
- `GASBoundaryProjectionSystemGroup`
- `GEExecutionCalculationExtensionSystemGroup`

不再把旧 `GASEffectGroup`、`GASAbilityGroup`、`GASCueGroup`、`GasStructuralPlaybackSystemGroup` 写成当前事实。

## P2-B：把 generated runtime 从“附属产物”改为“主链事实”

文档、任务树、审查表都需要把 `Assets/GAS/Generated/CodeGen/Runtime` 纳入 Runtime 主链范围。当前 generated systems 已经实际注册、读取 catalog、写 runtime state。

建议所有 Runtime 审查默认覆盖：

1. `Assets/GAS/Runtime`
2. `Assets/GAS/Generated/CodeGen/Runtime`
3. Demo 中注册进 GAS group 的 ECS extension systems

## P2-C：证据报告按 Core / Boundary / Demo 拆分

后续性能或合规报告应至少拆三类：

| 类别 | 包含 | 不应混淆 |
|---|---|---|
| CoreSimulation | Ability / GE / Attribute / ActiveEffect / Fact projection | 不混入 debugger/export/log UI |
| BoundaryProjection | Presentation / Replay / Diagnostics / Cue | 不作为 gameplay 权威状态 |
| Demo Integration | AutoChess bridge / session / result / log | 不代表 Runtime Core 通用成本 |

## P2-D：清理已不存在文件名

旧文档中大量出现的 `SHeadless*`、`HeadlessAutoChess*GeneratedRows`、`SAbilityCommit`、`SEffectApply` 等名称已与当前代码不一致。继续保留会干扰后续任务拆分。

建议文档改动时同步做 `rg` 检查：

```powershell
rg -n "SHeadless|HeadlessAutoChess|GASEffectGroup|GASAbilityGroup|GASCueGroup|GasStructuralPlaybackSystemGroup" 方案讨论/针对2.0的ECS架构的迭代方案讨论/00-当前架构事实
```

## P2-E：把 contract-only 与 runtime-proof 分开标注

`GASRuntimeFrameBudgetContract`、`GASRuntimeStructuralChangePlan`、`GASGeneratedDefinitionBakeContract` 等文件是 contract/plan。它们有治理价值，但不能替代：

- 系统是否注册进真实 group
- 数据是否被 hot path 读写
- Profiler/Journaling 是否证明成本与相位
- x50/x1000 battle hash 是否稳定

建议所有事实文件使用“contract-only / runtime-active / evidence-backed”三种状态标注。

## P2-F：AutoChess 配置链重新定基线

当前 AutoChessDemo 没有旧 Headless generated rows，`Config` 目录也没有业务 `.cs` 实体产物。后续若要恢复 Luban/SourceGenerator，需要先以当前 `GameRoom/Battle/Ecs/Integration` 业务模型为输入，而不是复活旧 Headless 文件结构。

## P2-G：补一页当前系统注册快照

`Runtime主链事实.md` 已列出当前注册系统。后续每次改调度时，建议同步更新：

1. `GASSystemScheduleContract` 注册表。
2. `RuntimeSystemRegistration.gen.cs` generated 注册表。
3. AutoChess `AutoChessRuntimeSystemBootstrap` 插入点。
4. 未注册但存在的系统类型。

## P2-H：文档日期不等于事实新鲜度

本目录以后应以“代码证据路径 + 当前审查日期”共同证明新鲜度。仅修改日期但保留旧文件名/旧 group/旧结论，视为未更新。
