## 归档结论

本轮破坏性瘦身计划已完成并归档。旧 gameplay EventBus 事实源、Damage/Attribute/Cue/Tag helper 兼容写入口、Presentation/Replay 双读、active mutation 无排序证据、Cue/EntityHelper/stream fallback 的全局 EntityManager 读取均已处理。

剩余的 owner-local store 终局、Layer 2 snapshot read model、结构变化 profiling 证据，不再作为本计划未完成项，后续应进入新的独立任务。

## 完成项

1. 删除 `DamageEventBuffer` / `EnqueueDamageEvent`，Damage 统一进入 `GameplayEventBuffer` typed fact。
2. 删除 `EventBusHelper.EnqueueAttributeChangeEvent`、`EnqueueCueRequest`、`EnqueueTagChangeEvent` 旧 gameplay observation enqueue API。
3. `PresentationOutboxProjectionSystem` 与 `ReplayLogSystem` 只读 `GameplayEventBuffer` typed fact，不再双读 Attribute/Cue/Tag/Damage 边界缓冲。
4. generated active mutation 只改 `GasGlueCodeGenPhases` 模板并重新生成 `.gen.cs`：active mutation command 进入 frame-local `NativeList`，按 `TargetAsc -> Sequence -> ParentContextId` 排序后应用。
5. `GEEffectCommandStreamComponent` 增加 active mutation 证据计数：`ActiveMutationCommandCount`、`ActiveMutationOwnerGroupCount`、`ActiveMutationMaxOwnerRange`、`ActiveMutationSortMoveCount`。
6. `EffectCommandSpecStream` 删除 `TryResolveGasManagerSingleton()` fallback；stream owner 只通过 `EnsureSingleton()` / `RegisterKnownSingleton()` 显式注册解析。
7. `EntityHelper` 改为显式 `EntityManager` 入口；`GameplayCueUnit` 构造签名破坏性要求 `EntityManager`；`GameplayCueBase` 通过 `SetRuntime(EntityManager, Entity)` 初始化 managed Cue runtime context。
8. `ASCCommandGateway` 写路径集中到 `ASCBoundaryCommandWriter`，`ASCReadModel` 显式接收 `EntityManager`。

本轮领取 R2/R3/R5 交叉切片：active mutation apply 已经是 ASC chunk-local，但跨 owner `SourceAttribute` 语义此前只能在 apply job 内保守落回 fallback，或在未来误回流成 `BufferLookup<AttributeValueBuffer>` alias。执行目标是让 active mutation 的跨 owner SourceAttribute 在 gather 与 apply 之间进入 frame-local snapshot lane，并把模板、生成物和静态门同步。

### 追加改动事实

1. `GasGlueCodeGenPhases.cs` 的 `RuntimeActiveEffectSystemsTemplate` 已新增 `ActiveMutationSourceAttributeSnapshots`，由 `GEActiveEffectMutationGatherJob : IJob` 使用 `[ReadOnly] BufferLookup<AttributeValueBuffer>` 和 `GASDefinitionCatalogBlob` 构建。
2. `RuntimeActiveEffect.gen.cs` 已由 `Tools\CodeGen\Generate-GAS-SourceGen.bat` 重新生成；`GEActiveEffectMutationChunkApplyJob : IJobChunk` 只消费 `NativeParallelHashMap<long, float> ActiveMutationSourceAttributeSnapshots`，不持有 `AttributeValueBuffer` lookup。
3. snapshot key 使用 `command.Sequence + modifierIndex`，同 owner SourceAttribute 仍读取当前 owner chunk attribute；跨 owner SourceAttribute 只走 snapshot map，miss 时保持显式 fallback 语义。
4. `Verify-GAS-RuntimeCoreBoundary.ps1` 已加入防回流门：要求模板和生成物都包含 `BuildActiveMutationSourceAttributeSnapshots`，要求 gather read-only `AttributeLookup`，要求 chunk apply snapshot map，并禁止重新生成 `TryReadAttributeValue(ref ownerResources, command.SourceAsc, ...)`。
5. `Assets/GAS/Generated/CodeGen/GasCodeGenValidationReport.md` 当前显示 `GeneratedRuntimeBoundaryHits=119`、`GeneratedRuntimeOwnershipHits=4`、`GeneratedRuntimeRandomWriteLookupHits=86`、`GeneratedRuntimeUnclassifiedBoundaryHits=0`。新增 `NativeParallelHashMap` 仍属于 generated runtime `MigrationProofOnly` native-container owner，不是 pure glue 完成态。

### 结论

1. Active mutation apply 的跨 owner `SourceAttribute` 不再需要在 chunk apply 内读取外部 `AttributeValueBuffer`；该 lane 已进入 read-only gather snapshot -> chunk-local apply。
2. 本轮 AutoChess 配置扫描没有发现 `SourceAttribute` 配置字样，因此 x50 业务链路不能写成 SourceAttribute 语义覆盖；它证明改动未破坏真实业务链路、structured snapshot owner 生效、active mutation / pending attribute 的 random lookup 与 migration carrier 指标保持 0。
3. 当前仍不是 scale-ready fan-in：active mutation command source 仍是 singleton DynamicBuffer，gather 仍是 serial `IJob`，snapshot map 容量 / spill / miss counter 仍需 R3/R4 继续补证据。
4. 下一轮应转向 pre-tick / execution calculation 的 SourceAttribute snapshot lane、snapshot miss/fallback debugger counter，以及 singleton stream carrier / generated instant delta record fan-in 拆分。

## 追加执行：AutoChess unit result structured snapshot 投影

> 追加日期：2026-06-07 | 稳定日志路径：`00-当前架构事实/_归档/2026-06-07-AutoChessBattleValidation-StructuredSnapshot-Run1.log`

本轮领取 R1/R6 中的 AutoChess live read 收口风险后，复核真实业务链路：`AutoChessBattleResultBuilder` 在已经拿到 `coreObservation.StructuredLog` 之后，仍调用 `session.CreateUnitResults()`，再由 `AutoChessGasCoreBridge.ReadCombatAttributes(...)` / `AutoChessGasBattleEntityLifecycle.ReadCombatAttributes(...)` 通过 `GASRuntimeShell.TryCaptureASCReadModel(...)` 捕获 live ECS snapshot。

### 追加改动事实

1. 新增 `AutoChessGasBattleUnitSnapshotProjector`，从 `GasStructuredLogExportSnapshot` 的 `AttributeChange` entries 读取 `TargetReportKey`，按 battle unit report key 回放 Health / Energy 最新值。
2. `AutoChessBattleResultBuilder` 改为把 `coreObservation.StructuredLog` 传入 `AutoChessBattleSession.CreateUnitResults(...)`，unit result 不再触发 live `ASCReadModel`。
3. `AutoChessBattleSession.TryResolveWinner()` 不再在 driver stats 不可用时 fallback 刷新单位 live attributes；胜负只由 driver stats 决定，final unit result 由 structured evidence 派生。
4. `AutoChessGasCoreBridge.ReadCombatAttributes(...)` 与 lifecycle live read helper 已删除。
5. `Verify-GAS-RuntimeCoreBoundary.ps1` 已加入防回流门：AutoChess session / bridge / lifecycle 不允许重新出现 `ReadCombatAttributes`、`RefreshUnits` 或 `TryCaptureASCReadModel`，validation report 必须输出 `snapshotOwner=AutoChessGasBattleUnitSnapshotProjector.StructuredLog`。
