## 归档结论

本轮破坏性瘦身计划已完成并归档。旧 gameplay EventBus 事实源、Damage/Attribute/Cue/Tag helper 兼容写入口、Presentation/Replay 双读、active mutation 无排序证据、Cue/EntityHelper/stream fallback 的全局 EntityManager 读取均已处理。

剩余的 owner-local store 终局、Layer 2 snapshot read model、结构变化 profiling 证据，不再作为本计划未完成项，后续应进入新的独立任务。

## 完成项

1. 删除 `DamageEventBuffer` / `EnqueueDamageEvent`，Damage 统一进入 `GameplayEventBuffer` typed fact。
2. 删除 `EventBusHelper.EnqueueAttributeChangeEvent`、`EnqueueCueRequest`、`EnqueueTagChangeEvent` 旧 gameplay observation enqueue API。
3. `PresentationOutboxProjectionSystem` 与 `ReplayLogSystem` 只读 `GameplayEventBuffer` typed fact，不再双读 Attribute/Cue/Tag/Damage 边界缓冲。
4. generated active mutation 只改 `GasGlueCodeGenPhases` 模板并重新生成 `.gen.cs`：active mutation command 进入 frame-local `NativeList`，按 `TargetAsc -> Sequence -> ParentContextId` 排序后应用。
5. `GEEffectCommandStreamComponent` 增加 active mutation 证据计数：`ActiveMutationCommandCount`、`ActiveMutationOwnerGroupCount`、`ActiveMutationMaxOwnerRange`、`ActiveMutationSortMoveCount`。
6. `EffectCommandSpecStream` 删除 `TryResolveGasManagerSingleton()` fallback；stream owner 只通过 `EnsureSingleton()` / `RegisterKnownSingleton()` 显式注册解析。
7. `EntityHelper` 改为显式 `EntityManager` 入口；`GameplayCueUnit` 构造签名破坏性要求 `EntityManager`；`GameplayCueBase` 通过 `SetRuntime(EntityManager, Entity)` 初始化 managed Cue runtime context。
8. `ASCCommandGateway` 写路径集中到 `ASCBoundaryCommandWriter`，`ASCReadModel` 显式接收 `EntityManager`。

本轮继续领取 singleton stream owner 风险中的低层 API 切口：`EffectCommandSpecStream` 不再提供 `BeginCommandWriter(EntityManager)` / `BeginGameplayEventWriter(EntityManager)` / `AppendCommand(EntityManager, ...)` / `AppendGameplayEvent(EntityManager, ...)` 这种内部自解析 singleton owner 的快捷入口。Runtime helper 必须先解析 stream owner 和 current frame，再显式构造 writer。

### 追加改动事实

1. `GEEffectCommandSpecStream.cs` 已删除 implicit singleton writer / append public API，只保留 `BeginCommandWriter(EntityManager, Entity, int)` 和 `BeginGameplayEventWriter(EntityManager, Entity, int)`。
2. `GameplayEffectRequestWriter`、`AbilityRuntimeActions`、`ExecutionCalculationRuntimeActions`、`EffectMagnitudeResolver`、`EffectRuntimeUtility` 已改为显式解析 stream owner 与 current frame 后写入 command / fact。
3. 对有业务状态写入的 helper，writer 不可用时仍保留原业务状态更新语义，只跳过 fact flush；纯 fact 写入路径在 writer 不可用时 no-op。
4. `Verify-GAS-RuntimeCoreBoundary.ps1` 已加入防回流门禁：禁止 stream 自身重新暴露 implicit singleton writer / append API，并禁止 runtime helper 重新调用旧入口。

### 结论

1. stream writer 的 hidden singleton owner API 已从 Runtime helper 可用面删除，并由静态门禁防回流。
2. AutoChess 业务字段保持通过，说明显式 owner/context writer 不破坏当前真实业务链路。
3. 当前只收缩了 helper API 面，不代表 singleton stream carrier 已被拆分；下一轮仍应继续推进 NativeStream / owner-local range / deterministic merge 和 SourceAttribute snapshot lane。
