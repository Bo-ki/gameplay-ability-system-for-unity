# EX-GAS 2.0 深度架构分析与 ECS 纯血重构方案

---

## 一、当前架构的核心问题诊断

### 问题 1：OOP 中间层污染了 ECS 核心（最严重）

`AbilityLogicBase` 是一个抽象 OOP 类，但它被直接嵌入 ECS System 的 `OnUpdate` 中调用： [1](#0-0) 

```csharp
// STryActivateAbility.cs - 注意第15行：[BurstCompile] 被注释掉了
//[BurstCompile]
public void OnUpdate(ref SystemState state)
{
    // ...
    var abilityLogic = state.EntityManager.GetComponentData<MCAbilityLogic>(ability);
    abilityLogic.Logic.ActivateAbility(globalTimer.ValueRO); // OOP虚函数调用！
}
```

`MCAbilityLogic` 是一个 **Managed Component**，它持有 OOP 对象引用： [2](#0-1) 

这导致：
- `STryActivateAbility`、`SAbilityTick` 等核心 System 全部**无法 Burst 编译**
- ECS 的 Job 并行化优势完全丧失
- GC 压力持续存在（Managed Component 不在 Chunk 内存中）

### 问题 2：EntityHelper 是一个危险的全局状态机 [3](#0-2) 

```csharp
public static class EntityHelper
{
    private static EntityCommandBuffer _ecb;          // 全局单例ECB
    private static bool _usingEcb;
    private static Dictionary<(Entity, Type), bool> _pendingComponents = new();
    private static List<Action> _deferredSetCommands = new();
    private static Dictionary<(Entity, Type), object> _pendingComponentData = new();
```

这个设计的问题：
- **线程不安全**：多个 System 并发时共享同一个 ECB 会崩溃
- **GC 压力**：每帧都在操作 `Dictionary<(Entity,Type), object>`，装箱拆箱严重
- **延迟命令链**：`_deferredSetCommands` 的 `List<Action>` 每帧分配闭包，是隐性 GC 炸弹 [4](#0-3) 

### 问题 3：AbilityController 的 O(n) 线性查找 [5](#0-4) 

```csharp
private Entity GetAbilityEntity(int abilityCode)
{
    var buffer = EntityHelper.GetBuffer<BAbility>(_asc);
    for (var i = 0; i < buffer.Length; i++)  // O(n) 遍历
    {
        var a = buffer[i].Ability;
        var abi = EntityHelper.GetComponentData<CAbilityBaseInfo>(a); // 每次都读ECS组件！
        if (abi.Code == abilityCode) return a;
    }
    return Entity.Null;
}
```

每次查找都要遍历 Buffer 并读取每个 Ability Entity 的组件数据，在自走棋场景中（数十个单位，每个单位多个技能），这是严重的性能问题。

### 问题 4：GASManager 的 Dictionary 绑定是 ECS→OOP 的反向耦合 [6](#0-5) 

```csharp
private static readonly Dictionary<Entity, AbilitySystemCell> _bindingAsc = new();
```

`AbilityLogicBase.Owner` 每次访问都要做字典查找： [7](#0-6) 

这意味着 ECS System 内部的逻辑（通过 `AbilityLogicBase`）在反向查询 OOP 层，形成了**双向耦合**，完全违背了 ECS 的设计哲学。

### 问题 5：Tag 系统的 NativeArray 内存管理是定时炸弹 [8](#0-7) 

```csharp
private void SetTagsInternal<T>(int[] tags, ...)
{
    var old = getter(com);
    if (old.IsCreated) old.Dispose();  // 手动释放
    _em.SetComponentData(_abilityEntity, factory(
        new NativeArray<int>(tags, Allocator.Persistent))); // 手动分配
}
```

`Allocator.Persistent` 的 NativeArray 散落在各个 Component 中，任何一处忘记 Dispose 都是内存泄漏。

### 问题 6：Luban 配置链路的潜力未被发掘

当前 Luban 只做了：
- 生成 Tag 常量（`XTag.gen.cs`）
- 生成表访问 API（`XLuban.gen.cs`） [9](#0-8) 

GE 的 ComponentConfig 是**运行时动态组装**的，没有利用代码生成来预先生成类型安全的 ECS Archetype 工厂，也没有结合 SourceGenerator 生成 Burst 兼容的注册代码。

## 二、新架构设计：纯血 ECS GAS

### 2.1 分层架构总览

```
┌──────────────────────────────────────────────────────────────────┐
│                    业务层 (OOP Shell)                             │
│   UIPresenter / NetworkAdapter / InputHandler                    │
│   ← 只通过 GASEventBus 接收事件，通过 GASFacade 发送命令 →       │
├──────────────────────────────────────────────────────────────────┤
│                    适配层 (Thin Adapter)                          │
│   GASFacade (静态命令API)  |  GASEventBus (ECS→OOP 事件桥)       │
│   GASLogger (结构化日志)                                          │
├──────────────────────────────────────────────────────────────────┤
│                  ECS GamePlay 核心层 (纯血)                       │
│   Components (全 unmanaged)  |  Systems (全 Burst)               │
│   Archetypes (预定义)        |  BlobAssets (静态数据)             │
├──────────────────────────────────────────────────────────────────┤
│              数据配置层 (Luban + SourceGenerator)                 │
│   Excel → Luban → JSON + gen.cs                                  │
│   SourceGenerator → ECS工厂代码 + System注册代码 + BlobBuilder   │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 核心改造：消灭 Managed Component，实现全 Burst

**关键思路**：用 `FunctionPointer<T>` 替代 OOP 虚函数，实现 Burst 兼容的多态。

```csharp
// ============================================================
// [新设计] 文件: Runtime/Ability/Component/CAbilityVTable.cs
// 用函数指针表替代 MCAbilityLogic（Managed Component）
// ============================================================

using Unity.Burst;
using Unity.Entities;

namespace GAS.Runtime
{
    // 能力生命周期函数签名（全部 Burst 兼容）
    public delegate void AbilityActivateDelegate(Entity ability, Entity owner, in GlobalTimer timer);
    public delegate void AbilityTickDelegate(Entity ability, Entity owner, in GlobalTimer timer);
    public delegate void AbilityEndDelegate(Entity ability, Entity owner, in GlobalTimer timer);
    public delegate void AbilityCancelDelegate(Entity ability, Entity owner, in GlobalTimer timer);

    // 替代 MCAbilityLogic 的纯 unmanaged 组件
    public struct CAbilityVTable : IComponentData
    {
        public FunctionPointer<AbilityActivateDelegate> OnActivate;
        public FunctionPointer<AbilityTickDelegate>     OnTick;
        public FunctionPointer<AbilityEndDelegate>      OnEnd;
        public FunctionPointer<AbilityCancelDelegate>   OnCancel;
    }

    // 能力自定义数据（替代 XParam OOP 对象）
    // 每种能力类型有自己的 unmanaged 数据组件
    public struct CAbilityCustomData : IComponentData
    {
        // 通用 payload，最多 128 字节
        // 具体能力通过 SourceGenerator 生成强类型访问器
        public unsafe fixed byte Payload[128];
    }
}
```

```csharp
using Unity.Burst;
```

```csharp
        public void OnUpdate(ref SystemState state)
        {
            var ecb = new EntityCommandBuffer(Unity.Collections.Allocator.Temp);
            var timer = SystemAPI.GetSingleton<GlobalTimer>();

            foreach (var (_, baseInfo, vTable, ability) in SystemAPI
                .Query<RefRO<CAbilityInTryActivate>,
                       RefRO<CAbilityBaseInfo>,
                       RefRO<CAbilityVTable>>()
                .WithEntityAccess())
            {
                var result = AbilityUtil.CanActivateAbility(ability, ref state);
                if (result == AbilityActivationResult.Success)
                {
                    ecb.AddComponent<CAbilityActive>(ability);
                    // 直接调用函数指针，Burst 编译！
                    vTable.ValueRO.OnActivate.Invoke(ability, baseInfo.ValueRO.Owner, timer);
                    AbilityUtil.CancelAbilitiesWithTags(ability, ref state, ref ecb);
                }

                // 通过 GASEventBus 发布事件（见 2.3 节）
                GASEventBus.PublishAbilityActivateResult(ability, result, ref ecb);
                ecb.RemoveComponent<CAbilityInTryActivate>(ability);
            }

            ecb.Playback(state.EntityManager);
            ecb.Dispose();
        }
    }
}
```

### 2.3 适配层：GASFacade + GASEventBus

OOP 层**不再直接操作 ECS**，只通过 Facade 发命令，通过 EventBus 接收结果：

```csharp
// ============================================================
// [新设计] 文件: Runtime/Adapter/GASFacade.cs
// OOP 与 ECS 之间的单向命令入口
// ============================================================

using Unity.Entities;

namespace GAS.Runtime
{
    /// <summary>
    /// OOP 层唯一合法的 ECS 操作入口。
    /// 所有方法只做"写入命令组件"，不读取 ECS 状态。
    /// 读取状态通过 GASEventBus 的事件回调获得。
    /// </summary>
    public static class GASFacade
    {
        private static EntityManager EM => GASManager.EntityManager;

        // ---- Ability 命令 ----

        public static void RequestActivateAbility(Entity ascEntity, int abilityCode, in AbilityInputData input)
        {
            // 找到 ability entity，写入命令组件
            var abilities = EM.GetBuffer<BAbility>(ascEntity);
            for (int i = 0; i < abilities.Length; i++)
            {
                if (abilities[i].Code == abilityCode)
                {
                    var abilityEntity = abilities[i].Ability;
                    EM.AddComponentData(abilityEntity, new CAbilityInTryActivate { Input = input });
                    GASLogger.Log(GASLogLevel.Command, ascEntity, $"RequestActivate:{abilityCode}");
                    return;
                }
            }
        }

        public static void RequestEndAbility(Entity ascEntity, int abilityCode)
        {
            var abilities = EM.GetBuffer<BAbility>(ascEntity);
            for (int i = 0; i < abilities.Length; i++)
            {
                if (abilities[i].Code == abilityCode)
                {
                    EM.AddComponent<CAbilityInTryEnd>(abilities[i].Ability);
                    return;
                }
            }
        }

        // ---- GE 命令 ----

        public static void RequestApplyEffect(Entity sourceAsc, Entity targetAsc, int geConfigId, int level = 1)
        {
            // 写入一个"待处理GE请求"组件到一个命令实体
            var cmdEntity = EM.CreateEntity();
            EM.AddComponentData(cmdEntity, new CApplyEffectRequest
            {
                Source    = sourceAsc,
                Target    = targetAsc,
                GeConfigId = geConfigId,
                Level     = level,
            });
            GASLogger.Log(GASLogLevel.Command, sourceAsc, $"RequestApplyGE:{geConfigId} → {targetAsc}");
        }
    }

    // 命令组件（纯 unmanaged）
    public struct CApplyEffectRequest : IComponentData
    {
        public Entity Source;
        public Entity Target;
        public int    GeConfigId;
        public int    Level;
    }

    // 输入数据（替代 XParam OOP 对象）
    public struct AbilityInputData
    {
        public Entity TargetEntity;
        public float3 TargetPosition;
        public int    ExtraInt;
    }
}
```

```csharp
// ============================================================
// [新设计] 文件: Runtime/Adapter/GASEventBus.cs
// ECS → OOP 的单向事件总线
// 使用 NativeQueue 作为 ECS 侧的写入缓冲，主线程轮询分发
// ============================================================

using System;
using System.Collections.Generic;
using Unity.Collections;
using Unity.Entities;

namespace GAS.Runtime
{
    // ECS 侧写入的事件结构（全 unmanaged）
    public struct GASEvent
    {
        public GASEventType Type;
        public Entity       Subject;   // 事件主体（ability/asc/ge entity）
        public Entity       Target;
        public int          IntParam;
        public float        FloatParam;
    }

    public enum GASEventType : byte
    {
        AbilityActivateSuccess,
        AbilityActivateFail,
        AbilityEnd,
        AbilityCancel,
        AttributeChanged,
        EffectApplied,
        EffectRemoved,
    }

    /// <summary>
    /// ECS System 写入事件，主线程（OOP）在 LateUpdate 中轮询消费。
    /// 完全避免了 ECS 内部调用 OOP 回调的反向耦合。
    /// </summary>
    public static class GASEventBus
    {
        // ECS 侧写入（Burst 兼容）
        private static NativeQueue<GASEvent> _eventQueue;

        // OOP 侧订阅
        private static readonly Dictionary<GASEventType, List<Action<GASEvent>>> _handlers = new();

        public static void Initialize()
        {
            _eventQueue = new NativeQueue<GASEvent>(Allocator.Persistent);
        }

        public static void Dispose()
        {
            if (_eventQueue.IsCreated) _eventQueue.Dispose();
        }

        // ECS System 调用（Burst 兼容，通过 NativeQueue.ParallelWriter）
        public static NativeQueue<GASEvent>.ParallelWriter GetWriter()
            => _eventQueue.AsParallelWriter();

        // OOP 层订阅
        public static void Subscribe(GASEventType type, Action<GASEvent> handler)
        {
            if (!_handlers.ContainsKey(type)) _handlers[type] = new List<Action<GASEvent>>();
            _handlers[type].Add(handler);
        }

        // 主线程每帧轮询（在 MonoBehaviour.LateUpdate 或 PlayerLoop 末尾调用）
        public static void Flush()
        {
            while (_eventQueue.TryDequeue(out var evt))
            {
                if (_handlers.TryGetValue(evt.Type, out var list))
                    foreach (var h in list) h(evt);
            }
        }
    }
}
```

```csharp
// ============================================================
// [新设计] 文件: Runtime/System/Tag/STagQuery.cs
// Burst 编译的 Tag 查询工具（静态方法，替代 TagHelper OOP 类）
// ============================================================

using Unity.Burst;
using Unity.Collections;
using Unity.Entities;

namespace GAS.Runtime
{
    [BurstCompile]
    public static class TagQuery
    {
        [BurstCompile]
        public static bool HasTag(ref CTagState state, int tagId)
        {
            foreach (var t in state.FixedTags)
                if (t == tagId || IsChildOf(t, tagId)) return true;
            foreach (var t in state.TemporaryTags)
                if (t == tagId || IsChildOf(t, tagId)) return true;
            return false;
        }

        [BurstCompile]
        public static bool HasAllTags(ref CTagState state, in FixedList32Bytes<int> required)
        {
            foreach (var r in required)
                if (!HasTag(ref state, r)) return false;
            return true;
        }

        [BurstCompile]
        public static bool HasAnyTags(ref CTagState state, in FixedList32Bytes<int> tags)
        {
            foreach (var t in tags)
                if (HasTag(ref state, t)) return true;
            return false;
        }

        // 层级匹配（通过 BlobAsset 查父节点）
        [BurstCompile]
        private static bool IsChildOf(int childTag, int parentTag)
        {
            // 利用 tag 编码规则：父 tag 是子 tag 的前缀
            // 例如 State.Stunned(0x0102) 是 State(0x01) 的子节点
            return (childTag & 0xFF00) == (parentTag & 0xFF00) && parentTag < childTag;
        }
    }
}
```

### 2.6 结构化日志系统

```csharp
// ============================================================
// [新设计] 文件: Runtime/Diagnostic/GASLogger.cs
// 结构化日志，支持 ECS 内部调用（Burst 兼容的轻量版本）
// ============================================================

using Unity.Collections;
using Unity.Entities;

namespace GAS.Runtime
{
    public enum GASLogLevel : byte { Verbose, Command, StateChange, Warning, Error }

    public struct GASLogEntry
    {
        public GASLogLevel Level;
        public Entity      Subject;
        public int         Frame;
        public FixedString128Bytes Message;
    }

    public static class GASLogger
    {
        private static NativeRingBuffer<GASLogEntry> _buffer; // 环形缓冲，固定内存
        private static bool _enabled;
        private static GASLogLevel _minLevel;

        public static void Initialize(int capacity = 4096, GASLogLevel minLevel = GASLogLevel.Command)
        {
            _buffer   = new NativeRingBuffer<GASLogEntry>(capacity, Allocator.Persistent);
            _enabled  = true;
            _minLevel = minLevel;
        }

        // 主线程调用（OOP 层）
        public static void Log(GASLogLevel level, Entity subject, string message)
        {
            if (!_enabled || level < _minLevel) return;
            _buffer.Push(new GASLogEntry
            {
                Level   = level,
                Subject = subject,
                Frame   = GASManager.CurrentFrame,
                Message = message,
            });
        }

        // ECS System 内调用（Burst 兼容，使用 FixedString）
        public static void LogBurst(GASLogLevel level, Entity subject, in FixedString128Bytes message)
        {
            if (!_enabled || level < _minLevel) return;
            _buffer.Push(new GASLogEntry
            {
                Level   = level,
                Subject = subject,
                Frame   = GASManager.CurrentFrame,
                Message = message,
            });
        }

        // 编辑器/调试工具轮询读取
        public static void Flush(System.Action<GASLogEntry> consumer)
        {
            while (_buffer.TryPop(out var entry))
                consumer(entry);
        }
    }
}
```

## 三、RPG 自走棋业务案例验证

### 3.1 场景描述

> **RPG 自走棋**：棋盘上有 8 个己方单位 + 8 个敌方单位，每回合自动战斗。
> 单位类型：战士、法师、刺客、牧师、坦克。
> 核心机制：技能释放、Buff/Debuff 叠加、属性联动、羁绊效果。

**能力实现（纯 ECS，全 Burst）**：

```csharp
// ============================================================
// [业务] 文件: AutoChess/Ability/FrostNovaAbility.cs
// 冰霜新星：对周围所有敌人造成伤害并冰冻
// ============================================================

using Unity.Burst;
using Unity.Collections;
using Unity.Entities;
using Unity.Mathematics;
using GAS.Runtime;

namespace AutoChess
{
    [GASAbility(typeId: XAbility.FrostNova)]
    [BurstCompile]
    public struct FrostNovaAbility
    {
        [BurstCompile]
        public static void Activate(Entity ability, Entity ownerAsc, in GlobalTimer timer)
        {
            var em = GASManager.EntityManager;

            // 1. 读取施法者属性（全 ECS，无 OOP 查找）
            var attrSets = em.GetBuffer<BEAttrSet>(ownerAsc);
            float magicPower = AttributeQuery.GetCurrentValue(
                attrSets, AttrSetCode.Combat, AttrCode.MagicPower);

            // 2. 查找范围内所有敌方单位（ECS 查询）
            var ownerCamp = em.GetComponentData<CChessUnit>(ownerAsc).CampId;
            var ownerPos  = em.GetComponentData<CChessUnit>(ownerAsc).BoardPosition;

            // 3. 对每个目标施加 GE（通过命令组件，不直接操作）
            // 写入 CApplyEffectRequest，由 SProcessApplyEffectRequest 系统处理
            var ecbSingleton = SystemAPI.GetSingleton<BeginSimulationEntityCommandBufferSystem.Singleton>();
            var ecb = ecbSingleton.CreateCommandBuffer(em.WorldUnmanaged);

            // 遍历棋盘上的敌方单位（通过 BoardIndex 组件查询）
            // 实际项目中用 SpatialHashMap 或 ChunkQuery 优化
            var allUnits = em.CreateEntityQuery(
                ComponentType.ReadOnly<CChessUnit>(),
                ComponentType.ReadOnly<CTagState>());

            var unitEntities = allUnits.ToEntityArray(Allocator.Temp);
            foreach (var targetAsc in unitEntities)
            {
                var targetUnit = em.GetComponentData<CChessUnit>(targetAsc);
                if (targetUnit.CampId == ownerCamp) continue; // 跳过友方
                if (!targetUnit.IsAlive) continue;

                int dist = math.abs(targetUnit.BoardPosition - ownerPos);
                if (dist > 2) continue; // 范围检查（自走棋棋盘距离）

                // 写入伤害 GE 请求
                var dmgCmd = ecb.CreateEntity();
                ecb.AddComponent(dmgCmd, new CApplyEffectRequest
                {
                    Source     = ownerAsc,
                    Target     = targetAsc,
                    GeConfigId = GEId.FrostNovaDamage,
                    Level      = em.GetComponentData<CChessUnit>(ownerAsc).Star,
                    ExtraFloat = magicPower, // 传递魔法强度给 MMC
                });

                // 写入冰冻 GE 请求
                var freezeCmd = ecb.CreateEntity();
                ecb.AddComponent(freezeCmd, new CApplyEffectRequest
                {
                    Source     = ownerAsc,
                    Target     = targetAsc,
                    GeConfigId = GEId.Frozen,
                    Level      = 1,
                });

                GASLogger.LogBurst(GASLogLevel.StateChange, ownerAsc,
                    $"FrostNova → target:{targetAsc.Index}");
            }
            unitEntities.Dispose();

            // 4. 触发冷却
            AbilityUtil.DoCooldown(ability);

            // 5. 触发消耗
            AbilityUtil.DoCost(ability);

            // 6. 技能立即结束（Instant 型技能）
            ecb.AddComponent<CAbilityInTryEnd>(ability);
        }

        [BurstCompile]
        public static void Tick(Entity ability, Entity owner, in GlobalTimer timer) { }

        [BurstCompile]
        public static void End(Entity ability, Entity owner, in GlobalTimer timer) { }

        [BurstCompile]
        public static void Cancel(Entity ability, Entity owner, in GlobalTimer timer) { }
    }
}
```

### 3.4 羁绊系统：纯 ECS 实现"冰系羁绊"

```csharp
// ============================================================
// [业务] 文件: AutoChess/System/SSynergyEffect.cs
// 羁绊效果系统：检测羁绊激活并施加全局 Buff
// 纯 ECS，全 Burst，无 OOP 中间层
// ============================================================

using Unity.Burst;
using Unity.Collections;
using Unity.Entities;
using GAS.Runtime;

namespace AutoChess
{
    [UpdateInGroup(typeof(SGLogic))]
    [UpdateBefore(typeof(SGAbility))]
    [BurstCompile]
    public partial struct SSynergyEffect : ISystem
    {
        [BurstCompile]
        public void OnUpdate(ref SystemState state)
        {
            // 统计各职业/种族数量
            var synergyCount = new NativeHashMap<int, int>(16, Allocator.Temp);

            foreach (var (unit, synergy) in SystemAPI
                .Query<RefRO<CChessUnit>, RefRO<CChessSynergy>>())
            {
                if (!unit.ValueRO.IsAlive) continue;
                foreach (var sid in synergy.ValueRO.ActiveSynergyIds)
                {
                    synergyCount.TryGetValue(sid, out int cnt);
                    synergyCount[sid] = cnt + 1;
                }
            }

            // 冰系羁绊：≥3 个冰系单位 → 所有冰系单位获得"冰霜护盾" Buff
            if (synergyCount.TryGetValue(SynergyId.Frost, out int frostCount) && frostCount >= 3)
            {
                var ecb = new EntityCommandBuffer(Allocator.Temp);
                foreach (var (unit, asc, entity) in SystemAPI
                    .Query<RefRO<CChessUnit>, RefRO<CAscRef>>()
                    .WithEntityAccess())
                {
                    if (!unit.ValueRO.IsAlive) continue;
                    // 检查是否已有冰霜护盾 Buff（避免重复施加）
                    var tagState = state.EntityManager.GetComponentData<CTagState>(asc.ValueRO.AscEntity);
                    if (TagQuery.HasTag(ref tagState, XTag.Buff_FrostShield)) continue;

                    // 写入 GE 请求
                    var cmd = ecb.CreateEntity();
                    ecb.AddComponent(cmd, new CApplyEffectRequest
                    {
                        Source     = asc.ValueRO.AscEntity,
                        Target     = asc.ValueRO.AscEntity,
                        GeConfigId = GEId.FrostShieldBuff,
                        Level      = frostCount >= 6 ? 2 : 1, // 6 冰系升级效果
                    });
                }
                ecb.Playback(state.EntityManager);
                ecb.Dispose();
            }

            synergyCount.Dispose();
        }
    }
}
```

### 3.5 UI 层：通过 GASEventBus 响应状态变化

```csharp
// ============================================================
// [业务] 文件: AutoChess/UI/UnitHPBarPresenter.cs
// UI 层完全不接触 ECS，只订阅事件
// ============================================================

using UnityEngine;
using GAS.Runtime;
using Unity.Entities;

namespace AutoChess.UI
{
    public class UnitHPBarPresenter : MonoBehaviour
    {
        [SerializeField] private UnityEngine.UI.Slider _hpSlider;
        private Entity _ascEntity;

        private void Start()
        {
            // 订阅属性变化事件
            GASEventBus.Subscribe(GASEventType.AttributeChanged, OnAttributeChanged);
        }

        private void OnDestroy()
        {
            // 取消订阅（OOP 层自己管理生命周期）
        }

        private void OnAttributeChanged(GASEvent evt)
        {
            if (evt.Subject != _ascEntity) return;
            if (evt.IntParam != AttrCode.HP) return; // IntParam 存 attrCode

            // evt.FloatParam 存新的 HP 百分比
            _hpSlider.value = evt.FloatParam;
        }
    }
}
```

## 四、新旧架构对比总结

| 维度 | 当前架构 | 新架构 |
|---|---|---|
| **Burst 覆盖率** | ~30%（核心 System 因 Managed Component 无法 Burst） | ~95%（全部 System 可 Burst） |
| **GC 压力** | 高（MCAbilityLogic、NativeArray 手动管理、Dictionary 装箱） | 极低（FixedList、BlobAsset、NativeQueue） |
| **OOP/ECS 耦合** | 双向耦合（ECS System 内调用 OOP 虚函数，OOP 直接读 ECS） | 单向（OOP→Facade→ECS，ECS→EventBus→OOP） |
| **Luban 利用率** | 常量生成 + 表访问 | 常量 + 表访问 + ECS 工厂 + BlobBuilder + SourceGen 注册 |
| **调试能力** | GASWatcher（Editor 专用） | GASLogger（结构化，运行时可用，支持回放） |
| **Tag 内存** | NativeArray（Persistent，手动 Dispose） | FixedList（栈内存，零 GC） |
| **Ability 多态** | OOP 虚函数（MCAbilityLogic） | FunctionPointer（Burst 兼容） |
| **自走棋 16 单位** | 每帧 GC 分配，System 串行 | 零 GC，System 可并行 Job |

### 架构分层职责最终定义

```
ECS 核心层（纯血）：
  ├── 所有 Component 必须 unmanaged
  ├── 所有 System 必须 [BurstCompile]
  ├── 禁止任何 OOP 对象引用（包括 string、List、Dictionary）
  └── 禁止调用 GASManager.GetAscFromEntity()（反向查 OOP）

适配层（Thin Adapter）：
  ├── GASFacade：OOP→ECS 的命令写入（只写，不读）
  ├── GASEventBus：ECS→OOP 的事件分发（NativeQueue 缓冲）
  └── GASLogger：结构化日志（NativeRingBuffer）

OOP Shell 层（业务交互）：
  ├── UI Presenter：订阅 GASEventBus，展示状态
  ├── NetworkAdapter：序列化 GASEvent，同步状态
  └── InputHandler：调用 GASFacade，发送命令
```

这个设计的核心价值在于：**ECS 层对 OOP 层完全透明**，OOP 层对 ECS 层完全无知，二者通过单向数据流（命令 + 事件）解耦，Luban + SourceGenerator 则消除了这个边界上所有的手写胶水代码。 [10](#0-9) [11](#0-10) [3](#0-2) [12](#0-11) [13](#0-12) [8](#0-7)

# RPG 自走棋完整业务案例

## 一、真实代码问题的精确定位（案例前置）

在展开案例之前，先把新架构要解决的问题精确对应到实际代码：

**问题 A：`BEAttrSet` 内嵌 `NativeArray` — 双重堆分配** [1](#1-0) 

```csharp
[InternalBufferCapacity(50)]
public struct BEAttrSet : IBufferElementData
{
    public int Code;
    public NativeArray<CAttributeData> Attributes; // ← 问题根源
}
```

`DynamicBuffer<BEAttrSet>` 本身在 Chunk 内存中，但每个元素里的 `NativeArray<CAttributeData>` 是独立的堆分配（`Allocator.Persistent`）。16个单位 × N个属性集 = N×16 个独立 NativeArray，全部在托管堆外，任何一处忘记 Dispose 就是内存泄漏。

**问题 B：`MCModifiers` 持有 OOP 抽象类引用** [2](#1-1) 

```csharp
public class MCModifiers : IComponentData  // Managed Component
{
    public EffectModifier[] Modifiers;      // 托管数组
}
// EffectModifier 内部：
public ModMagnitudeCalculationBase MMC;    // OOP 抽象类，虚函数
```

`MCModifiers` 是 `class`（Managed Component），`EffectModifier[]` 是托管数组，`MMC` 是 OOP 虚函数对象。这三层嵌套导致所有 GE 处理 System 无法 Burst。

**问题 C：`AttrSetController` 的 OOP 事件系统** [3](#1-2) 

```csharp
private void ChangeBaseValue(...)
{
    value = GASEventCenter.InvokeOnBaseValueChangeBefore(...); // OOP 事件
    data.Dirty = true;
    // ...
    GASEventCenter.InvokeOnBaseValueChangeAfter(...);          // OOP 事件
    EntityManager.AddComponent<CAttributeIsDirty>(Entity);
}
```

属性变化事件通过 `GASEventCenter`（OOP 事件中心）同步触发，这意味着属性重计算链路完全在主线程 OOP 层，`SUpdateAttributeCurrentValue` 的 `[BurstCompile]` 被注释掉就是直接证据： [4](#1-3) 

**问题 D：`GameplayEffectSpec` 是 1241 行的 OOP 巨类** [5](#1-4) 

```csharp
// "门面无 ECS" 的设计意图是好的，但实现上：

```

```csharp
// ============================================================
// [业务] AutoChess/System/SSynergyDetect.cs
// 统计场上各种族/职业数量，写入 CChessSynergy
// 全 Burst，无任何 OOP 引用
// ============================================================

[UpdateInGroup(typeof(SGPreTurn))]
[BurstCompile]
public partial struct SSynergyDetect : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        // 统计己方各种族数量
        var raceCount = new NativeHashMap<int, int>(8, Allocator.Temp);

        foreach (var (unit, configRef) in SystemAPI
            .Query<RefRO<CChessUnit>, RefRO<CUnitConfigRef>>())
        {
            if (!unit.ValueRO.IsAlive || unit.ValueRO.CampId != 0) continue;
            ref var cfg = ref configRef.ValueRO.Config.Value;
            raceCount.TryGetValue(cfg.RaceId, out int cnt);
            raceCount[cfg.RaceId] = cnt + 1;
        }

        // 判断羁绊激活阈值（阈值数据来自 BlobAsset，由 Luban 生成）
        var synergyBlob = SystemAPI.GetSingleton<CSynergyConfigRef>().Blob;

        // 写回每个单位的 CChessSynergy
        foreach (var (unit, configRef, synergy) in SystemAPI
            .Query<RefRO<CChessUnit>, RefRO<CUnitConfigRef>, RefRW<CChessSynergy>>())
        {
            if (!unit.ValueRO.IsAlive || unit.ValueRO.CampId != 0) continue;
            ref var cfg = ref configRef.ValueRO.Config.Value;

            synergy.ValueRW.ActiveSynergyIds.Clear();
            raceCount.TryGetValue(cfg.RaceId, out int myRaceCount);

            // 检查该种族的羁绊是否激活
            ref var synergyDefs = ref synergyBlob.Value.Definitions;
            for (int i = 0; i < synergyDefs.Length; i++)
            {
                ref var def = ref synergyDefs[i];
                if (def.RaceId == cfg.RaceId && myRaceCount >= def.MinCount)
                    synergy.ValueRW.ActiveSynergyIds.Add(def.SynergyTagId);
            }
        }

        raceCount.Dispose();
    }
}
```

### 6.3 属性重计算系统（替代当前 SUpdateAttributeCurrentValue）

```csharp
// ============================================================
// [新设计] Runtime/System/Attribute/SRecalculateAttr.cs
// 替代当前无法 Burst 的 SUpdateAttributeCurrentValue
//
// 当前问题：
//   - 调用 AttributeHelper.RecalculateCurrentValue（OOP）
//   - 依赖 GASEventCenter（OOP 事件系统）
//   - BEAttrSet 内嵌 NativeArray，无法在 Burst Job 中安全访问
//
// 新设计：
//   - CAttrModifierAccum 存储所有 GE 的增量累积
//   - 重算公式：CurrentValue = (BaseValue + AddMod) * MultMod
//   - 结果写入 CAttrCombat，同时写 GASEvent 通知 OOP 层
// ============================================================

[UpdateInGroup(typeof(SGAttribute))]
[BurstCompile]
public partial struct SRecalculateAttr : ISystem
{
    private NativeQueue<GASEvent>.ParallelWriter _eventWriter;

    [BurstCompile]
    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<CAttributeIsDirty>();
    }

    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        _eventWriter = GASEventBus.GetWriter();
        var ecb = new EntityCommandBuffer(Allocator.Temp);

        foreach (var (_, accum, attr, entity) in SystemAPI
            .Query<RefRO<CAttributeIsDirty>,
                   RefRO<CAttrModifierAccum>,
                   RefRW<CAttrCombat>>()
            .WithEntityAccess())
        {
            ref var a = ref attr.ValueRW;
            ref readonly var acc = ref accum.ValueRO;

            float oldHP  = a.HP;
            float oldATK = a.ATK;
            float oldDEF = a.DEF;

            // 重算公式（全 Burst，无 OOP）
            // ATKSpeed 特殊处理：Override 优先
            float newATKSpeed = acc.OverrideATKSpeed >= 0
                ? acc.OverrideATKSpeed
                : (a.BaseATKSpeed + acc.AddATKSpeed) * acc.MultATKSpeed;

            a.ATK        = math.max(0, (a.BaseATK + acc.AddATK));
            a.DEF        = math.max(0, (a.BaseDEF + acc.AddDEF) * acc.MultDEF);
            a.MagicPower = math.max(0, (a.BaseMagicPower + acc.AddMagicPower));
            a.ATKSpeed   = math.clamp(newATKSpeed, 10, 500);
            // HP 不重算（HP 是实时消耗值，不受 GE 重算影响，MaxHP 才受影响）

            // 写入属性变化事件（OOP 层 UI 通过 EventBus 接收）
            if (math.abs(oldDEF - a.DEF) > 0.01f)
            {
                _eventWriter.Enqueue(new GASEvent
                {
                    Type       = GASEventType.AttributeChanged,
                    Subject    = entity,
                    IntParam   = XAttr.Combat.DEF,
                    FloatParam = a.DEF,
                });
            }

            ecb.RemoveComponent<CAttributeIsDirty>(entity);
        }

        ecb.Playback(state.EntityManager);
        ecb.Dispose();
    }
}
```

### 6.5 GE 施加处理系统（替代当前 WipApplyEffect 链路）

```csharp
// ============================================================
// [新设计] Runtime/System/GameplayEffect/SProcessApplyRequest.cs
// 处理 CApplyEffectRequest 命令组件
//
// 对比当前架构：
//   当前：GameplayEffectSpec.ApplyTo() → OOP 调用链 → EntityHelper.AddComponent
//         MCModifiers 是 Managed Component，无法 Burst
//   新设计：纯 ECS 命令组件驱动，全 Burst
//           GEStaticBlob（BlobAsset）替代 MCModifiers
// ============================================================

[UpdateInGroup(typeof(SGGameplayEffect))]
[BurstCompile]
public partial struct SProcessApplyRequest : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var ecb = new EntityCommandBuffer(Allocator.Temp);
        var geRegistry = SystemAPI.GetSingleton<CGEBlobRegistry>();

        foreach (var (request, cmdEntity) in SystemAPI
            .Query<RefRO<CApplyEffectRequest>>()
            .WithEntityAccess())
        {
            ref readonly var req = ref request.ValueRO;
            var target = req.Target;
            var source = req.Source;

            if (!state.EntityManager.Exists(target) ||
                !state.EntityManager.Exists(source))
            {
                ecb.DestroyEntity(cmdEntity);
                continue;
            }

            // 1. 检查目标 Tag 免疫（ApplicationRequiredTags / ImmunityTags）
            var targetTagState = state.EntityManager.GetComponentData<CTagState>(target);
            ref var geBlob = ref geRegistry.GetBlob(req.GeStaticId).Value;

            // 检查免疫 Tag（目标身上有 GE 的 ImmunityTags 中的任意 Tag → 免疫）
            bool immune = false;
            for (int i = 0; i < geBlob.ImmunityTags.Length; i++)
            {
                if (TagQuery.HasTag(ref targetTagState, geBlob.ImmunityTags[i]))
                {
                    immune = true;
                    break;
                }
            }

            if (!immune)
            {
                if (geBlob.GeType == GEType.Instant)
                {
                    // Instant GE：直接计算并应用 Modifier，不创建 GE Entity
                    ApplyInstantModifiers(ref state, ref ecb, ref geBlob, source, target, req.ExtraFloat, req.Level);
                }
                else
                {
                    // Durational GE：创建 GE 实例 Entity
                    var geInstance = ecb.CreateEntity();
                    ecb.AddComponent(geInstance, new CEffectInUsage
                    {
                        Source = source,
                        Target = target,
                        Level  = req.Level,
                    });
                    ecb.AddComponent(geInstance, new CGEStaticRef
                    {
                        BlobRef    = geRegistry.GetBlob(req.GeStaticId),
                        ExtraFloat = req.ExtraFloat,
                    });
                    ecb.AddComponent<WipActivateEffect>(geInstance);

                    GASLogger.LogBurst(GASLogLevel.StateChange, target,
                        new FixedString128Bytes($"GE applied: id={req.GeStaticId}"));
                }
            }

            ecb.DestroyEntity(cmdEntity);
        }

        ecb.Playback(state.EntityManager);
        ecb.Dispose();
    }

    [BurstCompile]
    private static void ApplyInstantModifiers(
        ref SystemState state, ref EntityCommandBuffer ecb,
        ref GEStaticBlob geBlob, Entity source, Entity target,
        float extraFloat, int level)
    {
        var targetAttr = state.EntityManager.GetComponentData<CAttrCombat>(target);
        var sourceAttr = state.EntityManager.GetComponentData<CAttrCombat>(source);

        for (int i = 0; i < geBlob.Modifiers.Length; i++)
        {
            ref var mod = ref geBlob.Modifiers[i];
            // MMC 计算（FunctionPointer，Burst 兼容）
            float magnitude = MmcRegistry.Calculate(
                mod.MmcTypeId, mod.BaseMagnitude,
                ref sourceAttr, ref targetAttr, extraFloat, level);

            float oldVal = AttrAccessor.Get(ref targetAttr, mod.AttrCode);
            float newVal = mod.Operation switch
            {
                GEOperation.Add      => oldVal + magnitude,
                GEOperation.Minus    => oldVal - magnitude,
                GEOperation.Multiply => oldVal * magnitude,
                GEOperation.Override => magnitude,
                _                    => oldVal
            };
            AttrAccessor.Set(ref targetAttr, mod.AttrCode, newVal);
        }

        state.EntityManager.SetComponentData(target, targetAttr);
        ecb.AddComponent<CAttributeIsDirty>(target);
    }
}
```

### 6.6 MMC 函数指针注册表（替代 ModMagnitudeCalculationBase OOP 抽象类）

```csharp
// ============================================================
// [新设计] Runtime/Effect/Modifier/MmcRegistry.cs
// 替代 ModMagnitudeCalculationBase（OOP 抽象类 + 虚函数）
//
// 当前问题：
//   public class MCModifiers : IComponentData { EffectModifier[] Modifiers; }
//   public struct EffectModifier { public ModMagnitudeCalculationBase MMC; }
//   MMC 是 OOP 抽象类，CalculateMagnitude 是虚函数
//   → 整个 GE 处理链路无法 Burst
//
// 新设计：FunctionPointer 静态注册表，全 Burst
// ============================================================

public delegate float MmcCalculateDelegate(
    float baseMagnitude,
    ref CAttrCombat sourceAttr,
    ref CAttrCombat targetAttr,
    float extraFloat,
    int level);

public static class MmcTypeId
{
    public const int Flat            = 0; // 直接使用 baseMagnitude
    public const int FrostNovaDamage = 1; // MagicPower*1.5 - DEF*0.3
    public const int HealAura        = 2; // MagicPower*0.3
    public const int ShadowStrikeDmg = 3; // ATK*2.5
    public const int ScaledByLevel   = 4; // baseMagnitude * level
}

public static class MmcRegistry
{
    private static readonly FunctionPointer<MmcCalculateDelegate>[] _table
        = new FunctionPointer<MmcCalculateDelegate>[16];

    // 由 SourceGenerator 生成调用（启动时执行一次）
    public static void RegisterAll()
    {
        _table[MmcTypeId.Flat] = BurstCompiler
            .CompileFunctionPointer<MmcCalculateDelegate>(Flat);
        _table[MmcTypeId.FrostNovaDamage] = BurstCompiler
            .CompileFunctionPointer<MmcCalculateDelegate>(FrostNovaDamage);
        _table[MmcTypeId.HealAura] = BurstCompiler
            .CompileFunctionPointer<MmcCalculateDelegate>(HealAura);
        _table[MmcTypeId.ShadowStrikeDmg] = BurstCompiler
            .CompileFunctionPointer<MmcCalculateDelegate>(ShadowStrikeDmg);
    }

    [BurstCompile]
    public static float Calculate(int mmcTypeId, float baseMagnitude,
        ref CAttrCombat source, ref CAttrCombat target, float extra, int level)
        => _table[mmcTypeId].Invoke(baseMagnitude, ref source, ref target, extra, level);

    // ---- 具体 MMC 实现（全 Burst，纯数学，无 OOP）----

    [BurstCompile]
    private static float Flat(float baseMag, ref CAttrCombat src,
        ref CAttrCombat tgt, float extra, int level) => baseMag;

    // 冰霜新星伤害：MagicPower*1.5 - DEF*0.3（最低 1 点）
    // extra = 施法者 MagicPower（由 FrostNovaAbility.Activate 传入）
    [BurstCompile]
    private static float FrostNovaDamage(float baseMag, ref CAttrCombat src,
        ref CAttrCombat tgt, float extra, int level)
        => math.max(1f, extra * 1.5f - tgt.DEF * 0.3f) * level;

    // 治疗光环：MagicPower*0.3
    [BurstCompile]
    private static float HealAura(float baseMag, ref CAttrCombat src,
        ref CAttrCombat tgt, float extra, int level)
        => src.MagicPower * 0.3f;

    // 暗影突袭：ATK*2.5（暴击时 *CritDmg%）
    [BurstCompile]
    private static float ShadowStrikeDmg(float baseMag, ref CAttrCombat src,
        ref CAttrCombat tgt, float extra, int level)
    {
        float dmg = src.ATK * 2.5f;
        // 暴击判定（extra 传入随机数 0-100）
        if (extra < src.CritRate)
            dmg *= src.CritDmg / 100f;
        return math.max(1f, dmg - tgt.DEF * 0.2f);
    }
}
```

### 6.7 治疗光环 Period 触发系统

```csharp
// ============================================================
// [业务] Runtime/System/GameplayEffect/SEffectPeriodTick.cs
// 处理 Period GE 的周期触发（治疗光环每回合触发一次）
//
// 对比当前架构：
//   当前 SEffectPeriodTick 依赖 MCModifiers（Managed Component）
//   → 无法 Burst
// ============================================================

[UpdateInGroup(typeof(SGGameplayEffect))]
[BurstCompile]
public partial struct SEffectPeriodTick : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var timer = SystemAPI.GetSingleton<GlobalTimer>();
        var ecb   = new EntityCommandBuffer(Allocator.Temp);

        foreach (var (inUsage, geRef, entity) in SystemAPI
            .Query<RefRO<CEffectInUsage>, RefRO<CGEStaticRef>>()
            .WithAll<CEffectActive>()  // 只处理激活中的 GE
            .WithEntityAccess())
        {
            ref var blob = ref geRef.ValueRO.BlobRef.Value;
            if (blob.Period <= 0) continue; // 无 Period 配置

            // 检查是否到了触发时机（回合制：每 Period 回合触发一次）
            int elapsed = timer.CurrentTurn - blob.PeriodStartTurn;
            if (elapsed <= 0 || elapsed % blob.Period != 0) continue;

            var target = inUsage.ValueRO.Target;
            var source = inUsage.ValueRO.Source;

            if (!state.EntityManager.Exists(target)) continue;

            var targetAttr = state.EntityManager.GetComponentData<CAttrCombat>(target);
            var sourceAttr = state.EntityManager.GetComponentData<CAttrCombat>(source);

            // 应用 Period Modifier（治疗光环：HP += MagicPower*0.3）
            for (int i = 0; i < blob.PeriodModifiers.Length; i++)
            {
                ref var mod = ref blob.PeriodModifiers[i];
                float magnitude = MmcRegistry.Calculate(
                    mod.MmcTypeId, mod.BaseMagnitude,
                    ref sourceAttr, ref targetAttr,
                    geRef.ValueRO.ExtraFloat,
                    inUsage.ValueRO.Level);

                float oldHP = targetAttr.HP;
                targetAttr.HP = math.clamp(
                    targetAttr.HP + magnitude, 0, targetAttr.MaxHP);

                GASLogger.LogBurst(GASLogLevel.StateChange, target,
                    new FixedString128Bytes(
                        $"HealAura tick: +{magnitude:F1} HP ({oldHP:F0}→{targetAttr.HP:F0})"));
            }

            state.EntityManager.SetComponentData(target, targetAttr);
            ecb.AddComponent<CAttributeIsDirty>(target);

            // 写入治疗事件（UI 显示飘字）
            GASEventBus.GetWriter().Enqueue(new GASEvent
            {
                Type       = GASEventType.AttributeChanged,
                Subject    = target,
                IntParam   = XAttr.Combat.HP,
                FloatParam = targetAttr.HP / targetAttr.MaxHP, // HP 百分比
            });
        }

        ecb.Playback(state.EntityManager);
        ecb.Dispose();
    }
}
```

## 七、OOP Shell 层：UI 完全解耦

```csharp
// ============================================================
// [业务] AutoChess/UI/BattleHUDController.cs
// 战斗 HUD：血条、法力条、Buff 图标、伤害飘字
// 完全不接触 ECS，只订阅 GASEventBus
//
// 对比当前架构：
//   当前：BaseUnit.OnEnable() 直接调用
//         GASEventCenter.SetOnAttrBaseValueChangeBefore(ASC.Cell, ...)
//         GASEventCenter.RegisterOnAttrCurrentValueChangeAfter(ASC.Cell, ...)
//   问题：GASEventCenter 内部是三层嵌套 Dictionary，每次属性变化
//         都要 Tuple.Create(attrSetCode, attrCode) → GC 分配
//         且回调在 ECS System 内部同步触发，阻塞 System 执行
//   新设计：OOP 层只订阅 GASEventBus，ECS 执行完毕后主线程统一 Flush
// ============================================================

using System.Collections.Generic;
using UnityEngine;
using UnityEngine.UI;
using GAS.Runtime;
using Unity.Entities;

namespace AutoChess.UI
{
    public class BattleHUDController : MonoBehaviour
    {
        // 每个单位对应一个 HUD 视图
        private readonly Dictionary<Entity, UnitHUDView> _unitViews = new();

        private void OnEnable()
        {
            // 订阅属性变化事件（HP、Mana）
            GASEventBus.Subscribe(GASEventType.AttributeChanged, OnAttributeChanged);
            // 订阅技能命中事件（飘字）
            GASEventBus.Subscribe(GASEventType.AbilityHit,       OnAbilityHit);
            // 订阅 GE 施加事件（Buff 图标）
            GASEventBus.Subscribe(GASEventType.EffectApplied,    OnEffectApplied);
            GASEventBus.Subscribe(GASEventType.EffectRemoved,    OnEffectRemoved);
            // 订阅死亡事件
            GASEventBus.Subscribe(GASEventType.UnitDead,         OnUnitDead);
        }

        private void OnDisable()
        {
            GASEventBus.Unsubscribe(GASEventType.AttributeChanged, OnAttributeChanged);
            GASEventBus.Unsubscribe(GASEventType.AbilityHit,       OnAbilityHit);
            GASEventBus.Unsubscribe(GASEventType.EffectApplied,    OnEffectApplied);
            GASEventBus.Unsubscribe(GASEventType.EffectRemoved,    OnEffectRemoved);
            GASEventBus.Unsubscribe(GASEventType.UnitDead,         OnUnitDead);
        }

        // LateUpdate 中统一 Flush（ECS 所有 System 执行完毕后）
        private void LateUpdate() => GASEventBus.Flush();

        // ---- 事件处理 ----

        private void OnAttributeChanged(GASEvent evt)
        {
            if (!_unitViews.TryGetValue(evt.Subject, out var view)) return;

            switch (evt.IntParam) // IntParam = attrCode
            {
                case XAttr.Combat.HP:
                    // FloatParam = HP 百分比（ECS 侧已计算好）
                    view.HPBar.value = evt.FloatParam;
                    view.HPText.text = $"{evt.FloatParam * 100:F0}%";
                    break;
                case XAttr.Resource.Mana:
                    view.ManaBar.value = evt.FloatParam;
                    break;
            }
        }

        private void OnAbilityHit(GASEvent evt)
        {
            if (!_unitViews.TryGetValue(evt.Target, out var view)) return;
            // 在目标头顶生成伤害飘字
            var dmgText = ObjectPool.Get<DamageFloatText>();
            dmgText.Show(view.transform.position + Vector3.up * 2f,
                         $"-{evt.FloatParam:F0}",
                         evt.IntParam == XAbility.FrostNova ? Color.cyan : Color.red);
        }

        private void OnEffectApplied(GASEvent evt)
        {
            if (!_unitViews.TryGetValue(evt.Target, out var view)) return;
            // IntParam = GE 静态 ID，查图标配置
            view.BuffIconPanel.AddIcon(evt.IntParam, evt.Subject);
        }

        private void OnEffectRemoved(GASEvent evt)
        {
            if (!_unitViews.TryGetValue(evt.Target, out var view)) return;
            view.BuffIconPanel.RemoveIcon(evt.IntParam, evt.Subject);
        }

        private void OnUnitDead(GASEvent evt)
        {
            if (!_unitViews.TryGetValue(evt.Subject, out var view)) return;
            view.gameObject.SetActive(false);
            // 通知战场管理器检查胜负
            BattleManager.Instance.OnUnitDead(evt.Subject, evt.IntParam /* campId */);
        }

        public void RegisterUnit(Entity ascEntity, UnitHUDView view)
            => _unitViews[ascEntity] = view;

        public void UnregisterUnit(Entity ascEntity)
            => _unitViews.Remove(ascEntity);
    }
}
```

```
│       └─ 写入 GASEvent{AttributeChanged, HP} × 3（伤害后HP变化）
│
├─ [SGDeath]
│   └─ SDeathCheck:
│       └─ 敌方C: HP = 原HP - 292.5 = 负数 → 死亡
│           写入 GASEvent{UnitDead, Subject=敌方C, IntParam=1(敌方阵营)}
│
└─ GASEventBus.Flush()
    ├─ GASEvent{AbilityHit} × 3 → 飘字(-276, -255, -292)
    ├─ GASEvent{EffectApplied, 4001} × 2 → 冰冻图标（敌方A已有，跳过）
    ├─ GASEvent{AttributeChanged, HP} × 3 → HPBar 更新
    └─ GASEvent{UnitDead, 敌方C} → BattleHUDController.OnUnitDead()
        → BattleManager.OnUnitDead() → 检查胜负条件
```

## 八、`GASEventCenter` 的精确问题分析

这是当前架构中最隐蔽的性能问题，现在有了真实代码可以精确定位： [1](#2-0) 

```csharp
// 三层嵌套 Dictionary，每次属性变化的查找路径：
private static readonly Dictionary<Entity,
    Dictionary<Tuple<int, int>,          // ← Tuple.Create() 每次 GC 分配
        Func<float, float>>>
    _onBaseValueChangeBefore = new();
```

`SExecuteInstantEffectModifiers` 在每个 Modifier 处理时都调用： [2](#2-1) 

```csharp
// OnUpdate 没有 [BurstCompile]，因为：
// 1. MCModifiers 是 Managed Component（class）
// 2. GASEventCenter.InvokeOnBaseValueChangeBefore 是 OOP 静态方法
// 3. MmcHelper.Calculate 内部调用 ModMagnitudeCalculationBase.CalculateMagnitude（虚函数）
public void OnUpdate(ref SystemState state)  // ← 无 [BurstCompile]
{
    foreach (var modifier in modifiers.Modifiers)
    {
        // 每个 modifier 触发两次 Dictionary 查找 + Tuple 分配
        newValue = GASEventCenter.InvokeOnBaseValueChangeBefore(...);
        GASEventCenter.InvokeOnBaseValueChangeAfter(...);
    }
}
```

`MMCAttributeBased` 的 Track 模式更严重： [3](#2-2) 

```csharp
// Track 模式：每次被依赖属性变化，都通过 GASEventCenter 触发 OOP 回调
// 回调内部再调用 AttributeHelper.RecalculateCurrentValue（OOP）
// 这形成了：ECS System → GASEventCenter → OOP 回调 → ECS 操作 的反向调用链
_trackCallback = (_, _) =>
    AttributeHelper.RecalculateCurrentValue(_targetAsc.Entity, ...);
GASEventCenter.RegisterOnBaseValueChangeAfter(_sourceAsc, ...);
```

**新架构的替代方案**：属性依赖关系在 `CAttrModifierAccum` 中以增量形式维护，`SRecalculateAttr` 每帧统一重算，无需任何回调注册，无 GC，全 Burst。

## 十、完整架构对比总结

| 问题点 | 当前代码（精确定位） | 新架构方案 |
|---|---|---|
| **Burst 阻断** | `SExecuteInstantEffectModifiers.OnUpdate` 无 `[BurstCompile]`，因 `MCModifiers`(class) + `GASEventCenter` | `SProcessApplyRequest` 全 `[BurstCompile]`，`CAttrModifierAccum` 替代 `MCModifiers` |
| **GC 热点** | `GASEventCenter` 每次属性变化 `Tuple.Create(attrSetCode, attrCode)` 分配 | `GASEventBus` 用 `NativeQueue<GASEvent>`，零 GC |
| **反向耦合** | `MMCAttributeBased.Track` 在 ECS System 内注册 `GASEventCenter` OOP 回调 | `SRecalculateAttr` 增量重算，无回调注册 |
| **属性嵌套** | `BEAttrSet` 内嵌 `NativeArray<CAttributeData>`，双重堆分配 | `CAttrCombat`/`CAttrResource` 独立 unmanaged Component，全在 Chunk 内 |
| **Luban 利用** | `XAbility.gen.cs` 用反射注册 OOP 类型 | SourceGenerator 生成 `FunctionPointer` 注册，无反射 |
| **死亡判定** | 散落在 `GASEventCenter` 的 `OnHpChangeBefore` OOP 回调中 | `SDeathCheck` 独立 Burst System，时序明确 |
| **UI 耦合** | `BaseUnit.OnEnable` 直接注册 `GASEventCenter` 属性回调 | `BattleHUDController` 只订阅 `GASEventBus`，ECS 执行完后 `LateUpdate` 统一 Flush | [1](#2-0) [5](#2-4) [3](#2-2) [6](#2-5) [7](#2-6) [8](#2-7) [9](#2-8)
