## N1 闭合范围

当前完整 publish 边界按以下顺序执行：

```text
TargetPrepare
  -> TargetLocalStabilizationDeath
  -> TargetPublishPreflight
  -> TerminalPrepare
  -> RoutePrepare
  -> BoundaryPrepare
  -> FinalPublishFaultReduce
  -> FaultLatch
  -> TargetPublish
  -> TerminalPublish
  -> RoutePublish
  -> BoundaryPublish
```

Prepare 中的 period/application、终局裁决、跨 owner route 与 Boundary fact 只操作 Tick-local shadow/intent。Publish 前任一 fatal 会令同一 decision token 同时阻止四类 publisher、锁存 Session fault，并保持 source 已 admitted 的 committed prefix 与 fault-close 控制写契约。

当前 shadow 内部使用 EndFixed-owned、`ShouldPlayback=false` 的私有 ECB DynamicBuffer 适配器。它不 Playback，最终日志门未发现 native-container 异常或 TempJob 泄漏；但它只是正确性桥接，ECB DynamicBuffer 扩容仍可能产生 Persistent 分配抖动，并与“Prepare 不记录 ECB command”的规范字面约束存在争议，不能视为最终性能架构。

## N2 停止条件

1. 任一向量只绑定局部 helper 或替代测试却准备转 Green，立即停止。
2. 任何方案破坏 source committed prefix、统一 final token，或引入旧/新 Runtime 双写、fallback、第二事实源，立即停止。
3. `Pending` 被当成可退出状态，或 `ApprovedRed` 缺真实失败与完整批准记录，立即停止。
4. 保守 admission 若只靠“通常容量足够”而没有最坏需求上界，立即停止。
5. 私有 ECB 桥接没有先取得规模证据，不得宣称最终性能架构。
6. N2-G0 完整关闭前继续向手工/test builder 添加 gameplay schema，或让 incoming effect 持有 immunity query，立即停止。
7. 把本机可重算 evidence 写成可移植 release evidence，或用 transport `Consumed` 代替业务 terminal outcome，立即停止。
